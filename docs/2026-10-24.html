不要重写SID映射：动态电商搜索中生成式检索的拓扑保持

Don't Rewrite the SID Map: Topology Preservation for Generative Retrieval in Dynamic E-Commerce Search ↗

全文机构行（模型提取） · 论文更新于 2026-10-19（UTC）

面向工业生成式召回更新，给出可落地的“冻结旧SID、只插入新商品、warm-start”原则，并用67天日志控制实验和三周线上A/B支撑；适合做召回/索引更新策略的工程师。

研究问题

生成式检索把商品映射为离散SID并用自回归生成召回；电商新品持续到达、商业价值变化，需要周期性更新SID到商品映射与模型。问题在于映射更新会使模型已学到的解码路径失效，但映射变化程度与检索质量下降的定量关系、beam大小是否掩盖损伤、以及warm-start能否修复，此前缺乏系统刻画。

核心方法

论文不提出新算法，而把映射策略与训练策略解耦做控制实验。SID为三层：前两层由RQ-VAE结合query-item对比学习量化商品内容，第三层按点击/加购/购买等商业价值排序；采用混合碰撞分配，头部每前缀保留100个唯一token，尾部入碰撞桶。更新策略覆盖全量重映射、冻结映射和阈值重映射；训练策略覆盖不重训与从旧checkpoint warm-start，并在67天日志与TmallAPP线上A/B验证。

实验结果

  • 在FS/HC上刷新SID映射后，窄beam的HR@1下降41.78–62.05%，而beam=1000的宽beam降幅仅8.33–10.85%，宽beam会掩盖漂移严重性。
  • Frozen策略配合warm-start可同时提升旧品与新品：旧品HitRate约+10%、新品约+109%。
  • Full-Re经过warm-start后，旧品在beam=1000仍低于不重训Frozen，说明简单继续训练不能修复拓扑破坏。
  • 线上A/B中UCTCVR +0.29%、GMV +1.16%。

工程 insight 分析推断

  • 宽beam离线评估会掩盖SID漂移：线上若受延迟约束使用较窄beam，映射刷新造成的HR@1损失可能远高于宽beam报告；更新策略应按线上beam配置评估，而非只看beam=1000。
  • 重映射比例越低检索越稳，且Full-Re在warm-start后仍低于不重训Frozen；因此在频繁刷新价值层SID的系统中，优先冻结旧SID、仅插入新商品，比设计部分重映射或依赖短预算继续训练更稳。
  • 模型权重插值在该场景无观测收益，生产上可直接使用从旧checkpoint warm-start的新模型，减少额外超参和推理复杂度；但需按自身更新周期复验。

局限与阅读提醒

  • 作者明确将warm-start结论限定为简单“加载旧参数后在新数据上微调”，不声称拓扑变化不可逆，更稳健的持续学习框架可能部分恢复性能。
  • SID第三层嵌入时变商业价值，作者承认所报告的漂移严重程度带有value-aware SID方案特征；跨SID设计与跨平台泛化未在文中验证（后半句为分析判断）。

基线与增量：Instagram Feed 排序中的用户、物品与请求去偏

Baseline and Incremental: User, Item, and Request Debiasing in Instagram Feed Ranking ↗

全文机构行（模型提取） · 论文更新于 2026-10-20（UTC）

对工业推荐排序很有借鉴：不改模型、以配置化方式加去偏项，给出设计流程和四臂线上消融，并讨论权重调优、指标取舍和离线筛选的边界。

研究问题

Feed 排序器用多信号价值模型打分，每个参与预测同时包含用户/物品/请求基线（无论候选如何都会有的水平）与候选的增量超额。现有工作多直接移除基线；本文追问：是否应保留原始预测，并把增量部分作为独立加权项，以及如何统一三类去偏、选择设计点并在线上验证。

核心方法

作者把已部署的三类去偏统一为 Δ=m(p,b)[σ(k·d(p,b))−shift]，在价值模型中保留原始 p 并给 Δ 独立权重；b 分别取用户历史率、物品流行度/媒体类型或请求候选池统计量，比较尺度、幅度、斜率/中心为设计自由度。媒体类型偏置改走去偏标签。设计流程用离线分位相关和方差比判断是否拆分、用请求内形状选统计量，并估算服务成本；最后对 6 个已部署项做四臂在线随机实验（none/raw/incremental/both），在生产权重下比较。

实验结果

  • 四臂线上实验中，6 个已部署项的 13 个预设(term, metric)对里 11 个在点估计上 joint dominance；每项至少 1 个指标占优，4/6 在全部预设指标上占优。
  • 26 个直接臂间对比中 17 个显著为正、仅 1 个显著为负。
  • 对两个 time-spent gate，raw 项主要买时间，incremental 项改变展示构成（更短、非视频）；两者独立加权把时间与内容结构的取舍显式化。

工程 insight 分析推断

  • 对已有强基线成分的 engagement 信号，保留 raw 并加独立增量项，相当于在价值模型里增加一个可调维度；它只需配置和已有特征，通常不需要新增模型推理，适合快速上线/回滚。适用条件是基线特征可解析：稀疏特征上 clamp 会绑定，门控退化为额外 raw 权重。
  • 离线诊断应做高召回筛选，不做排序：高相关只说明基线成分存在，且 VM 持续调权会让机制指标仍在但 session 转化消失；上线测试仍是必要关卡。
  • 请求轴的低率偏态概率用 p75 而非 batch mean；均值版本在 seeMore 项上只动机制指标、未转化为 session。该结论来自单个请求项，迁移到其他信号需重新验证。

局限与阅读提醒

  • 四臂消融只有 6 个已部署项和 4 个权重点，不是权重扫描；6 项是 case series 而非样本，无法做跨项相关，也不能证明重调单臂无法达到同样效果（E12, E13）。
  • 离线诊断覆盖有限且离线到线上关系未定；论文报告不足 20% 的 Feed VM 信号有用户侧 rate 特征，约 6 个物品侧、约 5 个请求项，6 项研究不能定标（E18, E20）。

FineSID：从内容到相关性到个性化的渐进式 CTR 预测

Progressive Learning from Content to Relevance to Personalization for CTR Prediction ↗

全文机构行（模型提取） · 论文更新于 2026-10-21（UTC）

有淘宝十亿级离线评测、线上 A/B、冷启动和同商品创意消融，工程细节较完整，适合做多模态特征、语义 ID 与排序模型融合的工程师精读。

研究问题

多模态 CTR 要在搜索排序中同时利用商品内容、query 相关性和用户偏好；纯 ID 模型难处理冷启动，连续内容 embedding 与稀疏 ID 空间分布错配，而 RQ-VAE 等粗粒度 SID 压缩过强，丢失细粒度空间与文本信息。

核心方法

FineSID 把内容离散成与类别 ID 共用 lookup 的细粒度 SID：视觉用预训练多尺度 tokenizer 保留 30 个空间码，文本按字段保留独立 BPE/n-gram token；共享 HiFormer 式 latent-slot 排序器先用 Qwen3.5 教师给出的相关性软标签做全参预训练，再丢弃相关性头、接 CTR 头用点击日志全参微调。相对已有全局量化 SID，关键变化是保留 token 级、分模态分字段的离散接口。

实验结果

  • 淘宝离线 Table 2 中，相对 HiFormer+ID 基线，FineSID 的 AUC +0.25 pt、GAUC +0.26 pt，冷启动 AUC/GAUC +0.38/+0.34 pt，NSCTR 相对 +0.75%。
  • 淘宝主搜索线上 A/B 中，IPV/点击 +0.21%，GMV +0.85%，原文称两项改进均通过显著性检验。
  • 公开 MMCTR 上仅用 Stage I+III 的变体相对 HiFormer 的 AUC 提升 +0.77 pt，为文中报告方法中最大。
  • Table 3 消融中，去掉细粒度 SID（Stage I）后 AUC 增益仅 +0.03 pt，冷启动 AUC -0.03 pt，NSCTR 仅 +0.02%。

工程 insight 分析推断

  • 相比 RQ-VAE 式粗量化，把多尺度视觉/分字段文本离散成与类别 ID 共用 lookup 的 SID，可让现有 ID-based 排序器保留特征交互栈并吸收 token 级信号；重 tokenizer 离线、线上主要增加查表和底层投影，作者报告后链路延迟无明显增加，因此更适合后链路排序而非百万级召回。
  • 先用 query-item 相关性软标签对共享网络做全参预训练、再接点击微调，相当于把匹配先验注入冷启动场景；但该收益依赖教师相关性标注，缺少 relevance 标签时只能评估 Stage I+III 变体，迁移到无相关性监督场景需重新验证。
  • 同商品下 item ID 固定时，NSCTR 提升说明细粒度 SID 能利用图片/标题差异做创意优选，而不只是记忆商品 ID；线上只报告点击和 GMV，未拆分创意选择带来的独立增量。

局限与阅读提醒

  • 视觉 tokenizer 以图像重建预训练并在 Stage II 冻结，未按搜索相关性目标优化；作者将端到端联合微调列为未来工作。
  • 向早期召回、CVR 等其他搜索任务及 LLM 集成的泛化尚未验证；30 个多尺度 token 会加宽特征向量和底层投影成本，作者称后链路可接受，但极端低延迟召回仍需优化。

PAIR：面向 LinkedIn Premium 人推荐的偏好对齐意图检索

PAIR: Preference-Aligned Intent Retrieval for Premium People Recommendation at LinkedIn ↗

全文机构行（模型提取） · 论文更新于 2026-10-22（UTC）

生产系统论文，含离线基线对比与线上 A/B，适合关注 embedding 检索、互补意图建模、LLM 服务成本和多维度部署的工程师；方法取舍清晰。

研究问题

在 LinkedIn Premium Browsemaps 的人推荐中，相关候选人常是招聘者、客户等互补角色，而非与查询用户画像相似的人；通用嵌入和社交邻近信号会在检索阶段漏掉这类意图对齐候选人，且下游排序无法召回。论文要在不增加在线 LLM 重推理的前提下，用生产曝光日志学习偏好对齐的检索表示，并支持动态意图与不同延迟/存储预算。

核心方法

PAIR 把嵌入训练写成曝光条件偏好学习：点击候选为正，同 session 曝光未点击为 hard negatives，另加随机 negatives，正负比 1:3，用多负对比目标优化余弦相似度；计算形式同 InfoNCE，但负样本语义来自生产检索器的曝光分布。模型采用三塔：query profile 与 candidate 共享 LLM 编码器；history tower 对最近 K=10 个点击的预计算嵌入做位置感知注意力聚合，再与 query 向量归一化加性融合。历史更新只需 O(Kd) 向量运算，无需在线 LLM 推理；Matryoshka 联合训练 200/256/512/1024 维，一个模型服务多档预算。

实验结果

  • 离线 Premium 检索中，PAIR+P-ATT 的 MAR@100 为 0.450，较生产 Holistic-171 相对提升 56%。
  • 去掉历史为 0.436，加入 P-ATT 历史到 0.450，相对提升 3.2%；主要离线增益来自偏好微调而非历史模块。
  • 线上 A/B 替换生产嵌入后 CTR +7.5%、Premium retention +2.1%，页面加载延迟 +0.1%、推荐覆盖 -0.2%。
  • 256 维截断版本 MAR@100 0.432，相对存储 0.25×。

工程 insight 分析推断

  • 在招聘、B2B、创作者-广告主等跨角色推荐中，用曝光未点击构造 hard negatives 可能比单纯换大模型更能把嵌入空间从“相似”扭到“互补”；前提是曝光日志稳定且能接受历史策略选择偏差。
  • 轻量历史聚合适合日级/小时级意图刷新和 CPU 侧更新；但 query-agnostic 注意力表达力有限，若意图切换很快或 query-history 交互强，需评估更强序列模型是否值得额外服务成本。
  • Matryoshka 单模型多维度降低部署维护成本，但低维有质量损失：200 维 MAR@100 0.421、256 维 0.432，而 1024 维 0.450；应按面评估，不能默认低维无损。

局限与阅读提醒

  • 训练偏好仅来自历史曝光候选，存在选择偏差和反馈回路；原文将其视为生产权衡，并提出未来探索式采样（E13）。

面向迭代式ML Agent Harness的显式反馈契约

An Explicit Feedback Contract for Iterative ML-Agent Harnesses ↗

全文机构行（模型提取） · 论文更新于 2026-10-20（UTC）

若团队用LLM agent或AutoML迭代CTR/排序模型，或关心反复查询验证集导致离线指标虚高，这篇提供了可直接落地的反馈契约和停止规则；它不是新的推荐模型结构。

研究问题

迭代式ML Agent每轮读取精确验证分数、保留看似提升的编辑，会让有限验证集被自适应反复查询；真实提升与同量级噪声难以区分，最终报告偏向特定split。论文要回答：agent harness应如何规定可观察反馈、何时停止、何时可用测试集，以控制选择偏差。

核心方法

论文把Agent迭代视为自适应过拟合，提出显式反馈契约：验证标签和逐样本损失留在harness内，每轮只返回是否更新及当前最佳分数；预算与连续未更新patience预先固定；测试集使用时机预先规定。核心释放规则只在新候选相对当前champion的成对损失差超过其标准误时更新分数，阈值随任务噪声自适应、无需手调。

实验结果

  • 无信号对照（真实增益为0）中，读精确分数的agent报告增益0.0157，契约版报告0.0033。
  • 在论文的两个真实任务上，契约使验证-测试gap相对缩小约十分之一，测试表现略高而非下降。
  • 精确反馈在Criteo和无信号对照跑满30次预算、MSLR到第27次；契约版在三个任务上均明显更早停止。
  • 在Criteo的public validation size敏感性实验中，契约版在每个public size都有更小signed gap和更高mean test AUC；作者据此认为扩大验证集不能完全替代治理反馈通道（至少该范围内）。

工程 insight 分析推断

  • 工业AutoML/LLM-agent做CTR或排序迭代时，可把验证标签、逐样本loss和预测文件锁在harness内，只返回是否刷新最佳及当前最佳分数；这比单纯扩大验证集更直接地抑制自适应选择偏差。适用前提是候选可在同一验证样本上成对比较。
  • 释放阈值用paired standard error而非手调margin：论文中paired SE在固定margin网格上取得最小gap和最高test AUC且未更早停止，可作为默认策略；但理论保证只覆盖固定margin，生产化要监控最小阈值和停止频率。
  • NDCG按query分解，有效样本量是验证query数而非行数；排序任务用该契约时应按query级样本量重算阈值/统计功效，query少时不能把行数当作n。

局限与阅读提醒

  • 理论保证针对固定margin下释放的transcript，而非最终test score；部署的paired-SE规则仍是启发式，不保证最终模型更好。
  • 真实数据仅3个seed、两个数据集都是表格型，绝对差异小；论文未报告线上A/B，生产环境收益未知。

研究问题

工业推荐模型每次候选改动都需全量训练，消耗数千GPU小时，候选空间随架构、特征、超参组合迅速膨胀；LLM扩展律多预测同质Transformer的绝对损失，难以直接用于稀疏嵌入与稠密/序列组件耦合的异构推荐模型。论文研究能否用少量小规模代理训练预测全尺度相对表现，并正确排序候选假设。

  • TS-1 CTR头上EGP达到0.738τ_AA、ρ=0.800，原文称相对MAE改善15%。

  • 代理配置不能跨模型照搬：紧耦合特征交叉模型对嵌入缩放和组合缩放更敏感，组合可能把单轴尚可的排序变成负相关；工程上应在历史全量基准上按模型选择配置，并拒绝高符号翻转率组合。
  • GP的工程价值主要在带校准不确定性的拒识：原始代理已低于噪声地板时收益有限，而在基础模型CTR头这类代理失真场景可大幅降MAE；适合作为默认预测器并用不确定性阈值触发全量训练。

局限与阅读提醒

  • 全部实验为离线NE评测，论文未报告线上A/B、长期用户价值或业务指标；作者把适配NE之外的在线指标列为未来方向。

AGR：工具增强搜索的智能体生成式检索

AGR: Agentic Generative Retrieval with Tool-Augmented Search ↗

全文机构行（模型提取） · 论文更新于 2026-10-19（UTC）

适合正在做生成式召回、SID和特征服务的工程师：方法把特征调用嵌入beam search，成本对比和在线A/B都较具体；理论部分可略读。

研究问题

生成式检索（GR）用分层语义ID自回归召回，但工业系统依赖用户画像、行为、时效等异质特征。现有方法要么把所有特征静态拼进输入，要么按预设位置注入，导致服务成本上升、无关/冲突证据进入，且无法根据请求和已解码SID前缀决定“何时需要特征、选哪个特征、在哪个SID层级注入”。

核心方法

AGR把每类异质特征封装成带工具token的外部工具，调用结果编码为observation token；词表扩展为SID、工具、观测三类token，使工具调用与SID生成在同一自回归过程中交替。模型基于请求和已解码SID前缀决定是否调用、调用哪个工具，观测注入解码输入，工具token只作触发不回灌；推理在trie约束的beam search中为每条beam维护调用配额。训练先SID-only预训练，再用按特征适用性和层级判别度构造的工具增强轨迹微调，并缩放工具token损失。

实验结果

  • 在Industry、Qilin、JDSearch、KuaiSAR四个数据集上，AGR均优于TIGER；论文报告Recall相对提升6.4%–14.0%，MRR相对提升5.2%–19.7%。
  • 在Industry上，AGR（仅GSU工具）Recall@50=0.3237，接近直接编码长GSU序列；训练时间和服务成本分别降低81.8%和42.9%。
  • Industry消融中，AGR的Recall@50=0.3264，高于静态注入0.3159、query-guided gating 0.3161和固定位置工具注入0.3174。
  • Kuaishou Search在线A/B中，Relevance（top-4强相关PV占比）提升+0.205%。

工程 insight 分析推断

  • 把特征注入从“前置拼接”改为“解码中按需取用”，可把算力与上下文预算集中到当前前缀真正需要的特征；适用于已有分层SID和可在线调用的特征服务，但需要控制每beam工具配额与调用延迟。
  • 工具预算可优先投向模型不确定/基线易错的请求：论文中Recovery案例的工具调用率44.8%，远高于整体20.6%，提示按不确定性路由工具有望提升恢复率，但需在自有流量验证。
  • 工具返回必须编码为可区分的观测token，而不是只增加推理步；否则增益接近普通额外解码，工业实现应重视特征值编码与位置编码设计。

语义ID与特征接口：冻结、细粒度还是按需调用的取舍

围绕生成式推荐的语义ID与特征/推理接口，四篇样本给出不同取舍。2610.26105把更新稳定性放首位：冻结旧SID、只插入新品并warm-start，适合商品频繁新增且旧解码路径不能重写的场景，代价是新内容只能通过插入而非重映射表达。2610.29138追求内容表达力：多尺度视觉与分字段文本SID保留细粒度信息，并与类别ID共用lookup，适合冷启动和后链路排序，但特征变宽、依赖相关性教师。2610.26831追求调用效率：把异质特征工具化，在SID解码中按需注入，适合特征多且调用贵，但需beam配额和观测token设计。2610.30675追求推理固定开销：用latent token替代显式CoT并作为独立召回通道，适合有高质量教师和缓存服务的场景。以下为推断：更新频繁的系统应优先冻结旧SID并按线上beam评估；细粒度SID更适合后链路排序而非百万级召回；工具/推理token必须设预算与降级；上线前用线上候选预算复算离线指标。
