摘要

现代推荐系统通过将查询和候选物品嵌入到同一个统一空间中，随后进行近似最近邻搜索，以在给定查询嵌入的情况下选出排名靠前的候选，从而实现大规模召回。在本文中，我们提出一种新颖的生成式召回方法，其中召回模型自回归地解码目标候选的标识符。为此，我们为每个物品创建语义上有意义的码字元组，用作语义ID（Semantic ID）。给定用户会话中物品的语义ID，训练一个基于Transformer的序列到序列模型来预测用户接下来将与之交互的物品的语义ID。我们表明，使用所提出范式训练的推荐系统在各种数据集上显著优于当前的SOTA模型。此外，我们还表明，将语义ID纳入序列到序列模型可增强其泛化能力，这一点由对没有先前交互历史的物品所观察到的召回性能提升所证实。

1 引言

推荐系统帮助用户发现感兴趣的内容，广泛存在于视频[4, 43, 9]、应用[3]、商品[6, 8]和音乐[18, 19]等各种推荐领域。现代推荐系统采用召回—排序策略，其中在召回阶段选出一组可行候选，随后使用排序模型对其进行排序。由于排序模型仅处理其接收到的候选，因此期望召回阶段输出高度相关的候选。

构建召回模型有标准且成熟的方法。矩阵分解[19]在同一空间中学习查询和候选的嵌入。为了更好地捕捉数据中的非线性，近年来，采用内积将查询和候选嵌入映射到同一空间的双编码器架构[39]（即一个塔用于查询，另一个用于候选）变得流行。为了在推理期间使用这些模型，使用候选塔创建存储所有物品嵌入的索引。对于给定查询，使用查询塔获得其嵌入，并使用近似最近邻（ANN）算法进行召回。近年来，双编码器架构也被扩展到序列推荐[11, 24, 41, 17, 32, 6, 44]，显式地考虑用户—物品交互的顺序。

我们提出一种为序列推荐构建生成式召回模型的新范式。与传统的查询—候选匹配方法不同，我们的方法使用端到端生成模型直接预测候选ID。 我们提出利用Transformer[36]记忆（参数）作为推荐系统召回的端到端索引，这令人联想到Tay等人[34]将Transformer记忆用于文档召回的作法。我们将我们的方法称为用于生成式推荐器的Transformer索引（TIGER）。TIGER的高层概览如图1所示。TIGER的独特之处在于一种新颖的物品语义表示，称为“语义ID”（Semantic ID）——即从每个物品的内容信息导出的令牌序列。具体而言，给定物品的文本特征，我们使用预训练的文本编码器（例如SentenceT5[27]）生成稠密内容嵌入。然后对物品的嵌入应用量化方案，形成一组有序的令牌/码字，我们将其称为该物品的语义ID。最终，这些语义ID用于在序列推荐任务上训练Transformer模型。

将物品表示为语义令牌序列具有许多优势。在语义有意义的数据上训练Transformer记忆可以实现相似物品之间的知识共享。这使我们能够摒弃先前在推荐模型中用作物品特征的原子化随机物品ID[33, 42, 11, 8]。借助物品的语义令牌表示，模型更不易受推荐系统中固有反馈回路[1, 26, 39]的影响，从而使模型能够泛化到语料库中新添加的物品。此外，使用令牌序列进行物品表示有助于缓解与物品语料库规模相关的挑战；可用令牌表示的物品数量是序列中每个令牌基数之积。通常，物品语料库的规模可达数十亿量级，为每个物品学习唯一嵌入可能占用大量内存。虽然可以采用基于随机哈希的技术[16]来缩减物品表示空间，但在本工作中，我们表明使用语义上有意义的令牌进行物品表示是一种有吸引力的替代方案。本工作的主要贡献总结如下：

  1. 1.

    我们提出TIGER，一种新颖的基于生成式召回的推荐框架，它为每个物品分配语义ID，并训练召回模型来预测给定用户可能接触的物品的语义ID。

  2. 2.

    我们表明，以召回率和NDCG指标衡量，TIGER在多个数据集上优于现有的SOTA推荐系统。

  3. 3.

    我们发现，这种生成式召回的新范式为序列推荐系统带来了两项额外能力：1. 能够推荐新的和不频繁出现的物品，从而改善冷启动推荐；以及2. 能够使用可调参数生成多样化的推荐。

论文概览。在Section 2中，我们简要综述了推荐系统、生成式召回以及本文所使用的语义ID生成技术的相关文献。在Section 3中，我们解释了所提出的框架，并概述了我们用于语义ID生成的各种技术。我们在Section 4中给出实验结果，并在Section 5中对论文进行总结。

2 相关工作

序列推荐器。

在推荐系统中使用深度序列模型已发展出丰富的文献。GRU4REC[11]首次使用基于GRU的RNN进行序列推荐。 Li等人[24]提出了神经注意力会话推荐（NARM），其中使用注意力机制与GRU层来跟踪用户的长期意图。Zhang等人提出的AttRec[41]使用自注意力机制对用户在当前会话中的意图进行建模，并通过度量学习对用户—物品亲和度建模来确保个性化。同时，Kang等人也提出了SASRec[17]，其使用类似于仅解码器Transformer模型的自注意力。受掩码语言建模在语言任务中取得成功的启发，BERT4Rec[32]和Transformers4Rec[6]利用带有掩码策略的Transformer模型完成序列推荐任务。S3\text{S}^{3}-Rec[44]通过在四个自监督任务上进行预训练改进了数据表示，而不仅仅是掩码。上述模型为每个物品学习高维嵌入，并在最大内积搜索（MIPS）空间中进行ANN以预测下一个物品。相比之下，我们提出的技术TIGER使用生成式召回直接预测下一个物品的语义ID。

P5[8]微调预训练大语言模型以用于多任务推荐系统。P5模型依赖LLM分词器（SentencePiece分词器[29]）从随机分配的物品ID生成令牌。而我们使用基于物品内容信息学习得到的语义ID表示。在我们的实验（Table 2）中，我们证明基于物品语义ID表示的推荐系统比使用随机码获得的结果好得多。

语义ID。

Hou等人提出了VQ-Rec[12]，利用内容信息生成用于物品表示的“码”（类似于语义ID）。然而，他们的重点在于构建可迁移的推荐系统，并未以生成式方式将码用于召回。虽然他们也使用乘积量化[15]生成码，但我们使用RQ-VAE生成语义ID，从而得到物品的层次化表示（第4.2节）。在与我们同期的工作中，Singh等人[31]表明，在大规模推荐系统中，层次化语义ID可用于替代排序模型中的物品ID，从而改善模型泛化能力。

生成式召回。

尽管过去已提出学习搜索索引的技术[20]，但生成式召回是近期发展起来的用于文档召回的方法，其任务是从数据库中返回一组相关文档。一些例子包括GENRE[5]、DSI[34]、 NCI[37]和CGR[22]。关于相关工作的更详细内容见附录A。据我们所知，我们是首个使用物品语义ID表示为推荐系统提出生成式召回的工作。

3 所提出的框架

我们提出的框架包含两个阶段：

  1. 1.

    使用内容特征生成语义ID。这涉及将物品内容特征编码为嵌入向量，并将该嵌入量化为语义码字元组。所得的码字元组称为该物品的语义ID。

  2. 2.

    在语义ID上训练生成式推荐系统。使用语义ID序列在序列推荐任务上训练Transformer模型。

3.1 语义ID生成

在本节中，我们描述推荐语料库中物品的语义ID生成过程。我们假设每个物品都有相关联的内容特征，这些特征捕捉有用的语义信息（例如标题或描述或图像）。此外，我们假设可以使用预训练的内容编码器生成语义嵌入𝒙∈ℝd{\bm{x}}\in\mathbb{R}^{d}。例如，可以使用Sentence-T5[27]和BERT[7]等通用预训练文本编码器将物品的文本特征转换为语义嵌入。随后对语义嵌入进行量化，为每个物品生成语义ID。图2(a)给出了该过程的高层概览。

我们将语义ID定义为长度为mm的码字元组。 元组中的每个码字来自不同的码本。因此，语义ID可唯一表示的物品数量等于各码本大小之积。 尽管不同的语义ID生成技术会导致ID具有不同的语义特性，但我们希望它们至少具有以下特性： 相似物品（内容特征相似或其语义嵌入接近的物品）应具有重叠的语义ID。 例如，比较语义ID为(10,21,35)(10,21,35)的物品与语义ID为(10,21,40)(10,21,40)的物品，前者应比ID为(10,23,32)(10,23,32)的物品更相似。接下来，我们讨论用于语义ID生成的量化方案。

用于语义 ID 的 RQ-VAE。残差量化变分自编码器（Residual-Quantized Variational AutoEncoder，RQ-VAE）[40]是一种多级向量量化器，它对残差施加量化以生成码字元组（又称语义 ID）。该自编码器通过更新量化码本和 DNN 编码器-解码器参数进行联合训练。Fig. 3展示了通过残差量化生成语义 ID 的过程。

RQ-VAE 首先对输入 𝒙{\bm{x}} 进行编码，所用编码器为 ℰ{\mathcal{E}}，以学习潜在表示 𝒛:=ℰ⁢(𝒙){\bm{z}}:={\mathcal{E}}({\bm{x}})。在第零层（d=0d=0），初始残差直接定义为 𝒓0:=𝒛{\bm{r}}_{0}:={\bm{z}}。 在每一层 dd，我们有一个码本 𝒞d:={𝒆k}k=1K{\mathcal{C}}_{d}:=\{{\bm{e}}_{k}\}_{k=1}^{K}，其中 KK 为码本大小。 然后，将 𝒓0{\bm{r}}_{0} 量化，即将其映射到该层码本中最近的嵌入。 最近嵌入 𝒆cd{\bm{e}}_{c_{d}} 在 d=0d=0 处的索引，即 c0=arg⁢mini⁡‖𝒓0−𝒆k‖c_{0}=\operatorname*{arg\,min}_{i}\|{\bm{r}}_{0}-{\bm{e}}_{k}\|，表示第零个码字。 对于下一层 d=1d=1，残差定义为 𝒓1:=𝒓0−𝒆c0{\bm{r}}_{1}:={\bm{r}}_{0}-{\bm{e}}_{c_{0}}。 然后，与第零层类似，第一层的编码通过在第一层的码本中找到最接近 𝒓1{\bm{r}}_{1} 的嵌入来计算。 该过程递归重复 mm 次，以得到表示语义 ID 的 mm 个码字组成的元组。 这种递归方法从粗到细的粒度近似输入。 注意，我们选择使用大小为 KK 的独立码本，为 mm 个层级中的每一层各设置一个，而不是使用单个大小为 m⁢KmK 的码本。 这样做是因为残差的范数往往随着层数增加而减小，从而允许不同层级具有不同的粒度。

一旦我们得到语义 ID (c0,…,cm−1)(c_{0},\dots,c_{m-1})，𝒛{\bm{z}} 的量化表示便计算为 𝒛^:=∑d=0m−1𝒆ci\widehat{{\bm{z}}}:=\sum_{d=0}^{m-1}{\bm{e}}_{c_{i}}。 然后将 𝒛^\widehat{{\bm{z}}} 传递给解码器，解码器尝试重建输入 𝒙{\bm{x}}，所用映射为 𝒛^\widehat{{\bm{z}}}。RQ-VAE 损失定义为 ℒ⁢(𝒙):=ℒrecon+ℒrqvae{\mathcal{L}}({\bm{x}}):={\mathcal{L}}_{\text{recon}}+{\mathcal{L}}_{\text{% rqvae}}，其中 ℒrecon:=‖𝒙−𝒙^‖2{\mathcal{L}}_{\text{recon}}:=\|{\bm{x}}-\widehat{{\bm{x}}}\|^{2}，且 ℒrqvae:=∑d=0m−1‖sg⁢[𝒓i]−𝒆ci‖2+β⁢‖𝒓i−sg⁢[𝒆ci]‖2{\mathcal{L}}_{\text{rqvae}}:=\sum_{d=0}^{m-1}{\|\mbox{sg}[{\bm{r}}_{i}]-{\bm{% e}}_{c_{i}}\|^{2}}+\beta\|{\bm{r}}_{i}-\mbox{sg}[{\bm{e}}_{c_{i}}]\|^{2}。 这里 𝒙^\widehat{{\bm{x}}} 是解码器的输出，而 sg 是停止梯度操作 [35]。该损失联合训练编码器、解码器和码本。

如 [40] 所提出的，为防止 RQ-VAE 出现码本坍缩（即大多数输入仅被映射到少数几个码本向量），我们使用基于 k-means 聚类的码本初始化。具体而言，我们在第一个训练批次上应用 k-means 算法，并将质心用作初始化。

量化的其他替代方案。生成语义 ID 的一个简单替代方案是使用局部敏感哈希（LSH）。我们在小节 4.2 中进行了消融研究，发现 RQ-VAE 确实优于 LSH。另一种选择是分层使用 k-means 聚类 [34]，但它在不同簇之间丢失了语义含义 [37]。我们还尝试了 VQ-VAE，虽然它在召回阶段生成候选时与 RQ-VAE 表现相似，但它丢失了 ID 的层次性质，而这种层次性质赋予了第 4.3 节中讨论的许多新能力。

处理冲突。取决于语义嵌入的分布、码本大小的选择以及码字长度，可能会发生语义冲突（i.e.i.e.，即多个物品映射到同一语义 ID）。为了消除冲突，我们在有序语义编码的末尾附加一个额外的 token，使它们唯一。例如，如果两个物品共享语义 ID (12,24,52)(12,24,52)，我们附加额外的 token 来区分它们，将这两个物品分别表示为 (12,24,52,0)(12,24,52,0) 和 (12,24,52,1)(12,24,52,1)。为了检测冲突，我们维护一个将语义 ID 映射到相应物品的查找表。注意，冲突检测与修正在 RQ-VAE 模型训练完成后仅进行一次。此外，由于语义 ID 是整数元组，与高维嵌入相比，查找表在存储方面是高效的。

3.2 使用语义 ID 的生成式召回

我们通过按时间顺序对每个用户交互过的物品进行排序，为每个用户构建物品序列。然后，给定形式为 (item1,…,itemn)(\text{item}_{1},\dots,\text{item}_{n}) 的序列，推荐系统的任务是预测下一个物品 itemn+1\text{item}_{n+1}。我们提出一种直接预测下一个物品语义 ID 的生成式方法。形式化地，设 (ci,0,…,ci,m−1)(c_{i,0},\dots,c_{i,m-1}) 为长度为 mm 的语义 ID，对应的物品为 itemi\text{item}_{i}。然后，我们将物品序列转换为序列 (c1,0,…,c1,m−1,c2,0,…,c2,m−1,…,cn,0,…,cn,m−1)(c_{1,0},\dots,c_{1,m-1},c_{2,0},\dots,c_{2,m-1},\dots,c_{n,0},\dots,c_{n,m-1})。接着训练序列到序列模型来预测 itemn+1\text{item}_{n+1} 的语义 ID，即 (cn+1,0,…,cn+1,m−1)(c_{n+1,0},\dots,c_{n+1,m-1})。 鉴于我们框架的生成性质，解码器生成的语义 ID 可能不匹配推荐语料库中的任何物品。然而，正如我们在附录（Fig. 6）中所示，此类事件发生的概率很低。我们在附录 E 中进一步讨论了如何处理此类事件。

4 实验

数据集。我们在 Amazon Product Reviews 数据集 [10] 的三个公开真实世界基准上评估所提出的框架，该数据集包含 1996 年 5 月至 2014 年 7 月的用户评论和物品元数据。具体而言，我们将 Amazon Product Reviews 数据集的三个类别用于序列推荐任务：“Beauty”“Sports and Outdoors”和“Toys and Games”。我们在附录 C 中讨论数据集统计和预处理。

评估指标。我们使用 top-k Recall（Recall@K）和 K=5,10K=5,10 的归一化折损累计增益（NDCG@K）来评估推荐性能。

RQ-VAE 实现细节。如第 3.1 节所讨论的，RQ-VAE 用于量化物品的语义嵌入。我们使用预训练的 Sentence-T5 [27] 模型来获取数据集中每个物品的语义嵌入。具体而言，我们使用物品的内容特征（如标题、价格、品牌和类别）构造一个句子，然后将其传递给预训练的 Sentence-T5 模型，以获得维度为 768 的物品语义嵌入。

RQ-VAE 模型由三个组件组成： 一个 DNN 编码器，将输入的语义嵌入编码为潜在表示， 一个残差量化器，输出量化表示，以及 一个 DNN 解码器，将量化表示解码回语义输入嵌入空间。 编码器有三个中间层，大小分别为 512、256 和 128，使用 ReLU 激活，最终潜在表示维度为 3232。 为了量化该表示，进行三级残差量化。对于每一级，维护一个基数为 256256 的码本，其中码本中的每个向量维度为 3232。在计算总损失时，我们使用 β=0.25\beta=0.25。RQ-VAE 模型训练 20k 个 epoch 以确保高码本使用率（≥80%\geq 80\%）。我们使用 Adagrad 优化器，学习率为 0.4，批次大小为 1024。训练完成后，我们使用学习到的编码器和量化组件为每个物品生成一个 3 元组语义 ID。为避免多个物品被映射到同一语义 ID，我们为共享相同前三个码字的物品添加一个唯一的 4t⁢h4^{th} 编码，i.e.i.e. 两个与元组（7，1，4）关联的物品分别被分配为（7，1，4，0）和（7，1，4，1）（如果没有冲突，我们仍将 0 分配为第四个码字）。这使得推荐语料库中每个物品都获得一个长度为 4 的唯一语义 ID。

序列到序列模型实现细节。我们使用开源的 T5X 框架 [28] 实现基于 Transformer 的编码器-解码器架构。为使模型能够处理序列推荐任务的输入，序列到序列模型的词表包含每个语义码字的 token。具体而言，词表包含 1024（256×4256\times 4）个 token 来表示语料库中的物品。除物品的语义码字外，我们还在词表中添加用户特定的 token。为限制词表大小，我们仅为用户 ID 添加 2000 个 token。我们使用哈希技巧 [38] 将原始用户 ID 映射到 2000 个用户 ID token 之一。我们将输入序列构造为：用户 ID token 后接对应用户物品交互历史的语义 ID token 序列。我们发现，将用户 ID 添加到输入中可使模型对召回的物品进行个性化。

我们为基于 Transformer 的编码器和解码器模型各使用 4 层，每层具有 6 个维度为 64 的自注意力头。我们对所有层使用 ReLU 激活函数。MLP 维度和输入维度分别设置为 1024 和 128。我们使用的 dropout 为 0.1。总体而言，该模型约有 13 百万个参数。我们针对“Beauty”和“Sports and Outdoors”数据集训练该模型 200k 步。由于“Toys and Games”数据集规模较小，仅训练 100k 步。我们使用的批次大小为 256。学习率为 0.010.01，用于前 10k 步，之后遵循逆平方根衰减调度。

4.2 物品表示

在本节中，我们分析 RQ-VAE 语义 ID 的几个重要特性。具体而言，我们首先进行定性分析，以观察语义 ID 的层次结构特性。接着，我们通过将性能与另一种基于哈希的量化方法进行对比，来评估我们使用 RQ-VAE 进行量化这一设计选择的重要性。最后，我们进行消融实验，通过将 TIGER 与使用随机 ID 作为物品表示的序列到序列模型进行比较，来研究使用语义 ID 的重要性。

我们还通过固定c1c_{1}并可视化c2c_{2}所有可能取值的类别分布，结果见Fig. 4(b)，来可视化 RQ-VAE 语义 ID 的层次结构特性。我们再次发现，第二个码字c2c_{2}进一步将c1c_{1}所捕获的高层语义划分为细粒度类别。RQ-VAE 学习到的语义 ID 的层次结构特性开辟了一系列新能力，这些将在第4.3节中讨论。与基于随机原子 ID 学习物品嵌入的现有推荐系统不同，TIGER 使用语义 ID，其中语义相似的物品具有重叠的码字，这使得模型能够有效地共享数据集中语义相似物品的知识。

哈希与 RQ-VAE 语义 ID 的比较。我们通过将 RQ-VAE 与局部敏感哈希（LSH）[14, 13, 2]用于语义 ID 生成进行对比，来研究 RQ-VAE 在我们框架中的重要性。LSH 是一种流行的哈希技术，可以很容易地适配我们的设定。为生成 LSH 语义 ID，我们使用hh个随机超平面𝒘1,…,𝒘h{\bm{w}}_{1},\dots,{\bm{w}}_{h}对嵌入向量𝒙{\bm{x}}执行随机投影，并计算如下二值向量：(1𝒘1⊤⁢𝒙>0,…,1𝒘h⊤⁢𝒙>0)(1_{{\bm{w}}_{1}^{\top}{\bm{x}}>0},\dots,1_{{\bm{w}}_{h}^{\top}{\bm{x}}>0})。该向量按c0=∑i=1h2i−1⁢1𝒘i⊤⁢𝒙>0c_{0}=\sum_{i=1}^{h}2^{i-1}1_{{\bm{w}}_{i}^{\top}{\bm{x}}>0}转换为整数编码。此过程使用一组独立的随机超平面重复mm次，得到mm个码字(c0,c1,…,cm−1)(c_{0},c_{1},\dots,c_{m-1})，我们将其称为 LSH 语义 ID。

在表2中，我们将 LSH 语义 ID 与我们所提出的 RQ-VAE 语义 ID 的性能进行比较。在该实验中，对于 LSH 语义 ID，我们使用h=8h=8个随机超平面并设置m=4m=4，以确保基数与 RQ-VAE 相当。超平面的参数从标准正态分布中随机采样，这确保了超平面具有球对称性。我们的结果表明 RQ-VAE 始终优于 LSH。这说明，在给定相同的基于内容的语义嵌入的情况下，通过非线性深度神经网络（DNN）架构学习语义 ID，比使用随机投影能获得更好的量化效果。

随机 ID 与语义 ID 的比较。我们还在生成式检索推荐系统中比较了语义 ID 的重要性。具体而言，我们将随机生成的 ID 与语义 ID 进行比较。为生成随机 ID 基线，我们为每个物品分配mm个随机码字。长度为mm的物品随机 ID 即为(c1,…,cm)(c_{1},\dots,c_{m})，其中cic_{i}从{1,2,…,K}\{1,2,\dots,K\}中均匀随机采样。我们将随机 ID 基线的m=4m=4和K=255K=255设置为与 RQ-VAE 语义 ID 相近的基数。随机 ID 与 RQ-VAE 及 LSH 语义 ID 的比较如表2所示。我们看到语义 ID 始终优于随机 ID 基线，凸显了利用基于内容的语义信息的重要性。

4.3 新能力

我们描述直接源自我们所提出的生成式检索框架的两项新能力，即冷启动推荐和推荐多样性。我们将这些能力称为“新”能力，是因为现有的序列推荐模型（参见第4.1节中的基线）无法直接用于满足这些真实世界的用例。这些能力源于基于 RQ-VAE 的语义 ID 与我们框架的生成式检索方法之间的协同作用。我们在以下各节中讨论 TIGER 如何在这些设定中使用。

冷启动推荐。在本节中，我们研究我们所提出框架的冷启动推荐能力。由于真实世界推荐语料库的快速变化特性，新物品不断被引入。由于新添加的物品在训练语料库中缺乏用户曝光，使用随机原子 ID 作为物品表示的现有推荐模型无法检索新物品作为候选。相比之下，TIGER 框架可以轻松执行冷启动推荐，因为它在预测下一个物品时利用了物品语义。

对于此分析，我们考虑来自 Amazon Reviews 的 Beauty 数据集。为模拟新添加的物品，我们从训练数据划分中移除5%的测试物品。我们将这些被移除的物品称为未见物品。从训练划分中移除物品确保了关于未见物品不存在数据泄漏。 与前文一样，我们使用长度为4的语义 ID 来表示物品，其中前3个词元使用 RQ-VAE 生成，第4t⁢h4^{th}个词元用于确保所有已见物品都存在唯一 ID。我们在训练划分上训练 RQ-VAE 量化器和序列到序列模型。训练完成后，我们使用 RQ-VAE 模型为数据集中的所有物品生成语义 ID，包括物品语料库中的任何未见物品。

给定模型预测的语义 ID (c1,c2,c3,c4)(c_{1},c_{2},c_{3},c_{4})，我们检索具有相同对应 ID 的已见物品。注意，根据定义，模型预测的每个语义 ID 最多只能匹配训练数据集中的一个物品。此外，具有相同前三个语义词元i.e.i.e. (c1,c2,c3)(c_{1},c_{2},c_{3})的未见物品会被加入检索候选列表。最后，在检索一组 top-K 候选时，我们引入一个超参数ϵ\epsilon，它指定了我们框架所选未见物品的最大比例。

我们在Fig. 5中比较了 TIGER 与 k 近邻（KNN）方法在冷启动推荐设定下的性能。对于 KNN，我们使用语义表示空间来执行最近邻搜索。我们将基于 KNN 的基线称为 Semantic_KNN。Fig. 5(a)表明，我们的框架在ϵ=0.1\epsilon=0.1下，在所有 Recall@K 指标上始终优于 Semantic_KNN。在Fig. 5(b)中，我们提供了我们的方法与 Semantic_KNN 在不同ϵ\epsilon取值下的比较。对于所有ϵ≥0.1\epsilon\geq 0.1设置，我们的方法都优于基线。

推荐多样性。虽然 Recall 和 NDCG 是用于评估推荐系统的主要指标，但预测的多样性是另一个关键关注目标。多样性差的推荐系统可能有损用户的长期参与度。在这里，我们讨论我们的生成式检索框架如何用于预测多样的物品。我们表明，解码过程中基于温度的采样可以有效地用于控制模型预测的多样性。虽然基于温度的采样可以应用于任何现有推荐模型，但得益于 RQ-VAE 语义 ID 的特性，TIGER 允许在不同层次级别上进行采样。例如，对语义 ID 的第一个词元进行采样允许从粗粒度类别中检索物品，而对第二个/第三个词元进行采样则允许在某一类别内采样物品。

我们使用 Entropy@K 指标定量衡量预测的多样性，其中熵是针对模型预测的 top-K 物品的真实类别分布计算的。我们在表3中报告了不同温度值下的 Entropy@K。我们观察到，解码阶段的温度采样可以有效地用于增加物品真实类别的多样性。我们还在表4中进行了定性分析。

4.5 无效 ID

由于模型自回归地解码目标语义 ID 的码字，模型有可能预测出无效 ID（即，不映射到推荐数据集中任何物品的 ID）。在我们的实验中，我们使用长度为44的语义 ID，每个码字的基数为256256（即，每一级的码本大小 = 256）。该组合所张成的可能 ID 数为=2564=256^{4}，约为4万亿。另一方面，我们所考虑数据集中的物品数为10K-20K（见表6）。尽管有效 ID 的数量仅占整个 ID 空间的一小部分，但我们观察到模型几乎总是预测出有效 ID。我们将 TIGER 产生的无效 ID 比例表示为检索物品数KK的函数，并在图6中进行可视化。对于 top-10预测，三个数据集的无效 ID 比例在∼0.1%−1.6%\sim 0.1\%-1.6\%之间变化。为抵消无效 ID 的影响并始终获得 top-10有效 ID，我们可以增大束搜索大小并过滤掉无效 ID。

需要注意的是，尽管会生成无效 ID，TIGER 与用于序列推荐的其他流行方法相比仍取得了最先进的性能。处理无效词元的一种扩展方法是在模型生成无效词元时进行前缀匹配。语义 ID 的前缀匹配将允许检索与模型生成的词元具有相似语义含义的物品。鉴于我们 RQ-VAE 词元的层次结构特性，前缀匹配可以看作是模型预测物品类别而非物品索引。注意，这样的扩展可以进一步提高 recall/NDCG 指标。我们将此类扩展留作未来工作。

5 结论

本文提出了一种名为 TIGER 的新范式，使用生成模型在推荐系统中召回候选。该方法的基础是一种新颖的物品语义 ID 表示，它在内容嵌入上使用分层量化器（RQ-VAE）来生成构成语义 ID 的词元。我们的框架所提供的模型可以在无需构建索引的情况下进行训练和部署——transformer 记忆充当物品的语义索引。我们注意到，我们的嵌入表基数不会随物品空间基数的增长而线性增长，这相对于需要在训练期间创建大型嵌入表或为每个物品生成索引的系统而言是有利的。通过在三个数据集上的实验，我们表明我们的模型能够达到 SOTA 的召回性能，同时能泛化到新的、未见过的物品。

Appendix A 相关工作（续）

生成式召回

文档召回传统上涉及训练一个 2-塔模型，该模型将查询和文档都映射到同一个高维向量空间，然后对所有文档执行针对该查询的 ANN 或 MIPS 以返回最接近的文档。这种技术存在一些缺点，例如需要大型嵌入表 [22, 23]。生成式召回是最近提出的一种技术，旨在通过逐词元地生成文档的标题、名称或文档 id 字符串来修复传统方法的一些问题。Cao 等人 [5] 提出了用于实体召回的 GENRE，它使用基于 transformer 的架构，逐词元地返回给定查询中所引用实体的名称。Tay 等人 [34] 提出了用于文档召回的 DSI，这是第一个为每个文档分配结构化语义 DocID 的系统。然后，给定一个查询，该模型逐词元地自回归返回该文档的 DocID。DSI 的工作标志着 IR 向生成式召回方法范式的转变，并且是端到端 Transformer 在召回应用中首次成功的应用。 随后，Lee 等人 [23] 表明，生成式文档召回即使在多跳设置中也很有用；在多跳设置中，复杂查询无法由单个文档直接回答，因此他们的模型以思维链的方式生成中间查询，以最终为复杂查询生成输出。 Wang 等人 [37] 对基于分层 kk-均值聚类的语义 DocID 作出补充；这些 DocID 来自 Tay 等人 [34]，而补充方法是提出一种专门考虑语义 DocID 中前缀的新解码器架构。 在 CGR [22] 中，作者提出了一种同时利用双编码器技术和生成式召回技术的方法，允许其编码器-解码器模型的解码器学习单独的 上下文化 嵌入，这些嵌入在本质上存储文档信息。 据我们所知，我们是第一个将使用自编码器（RQ-VAE [40, 21]）创建的生成式语义 ID 用于召回模型的工作。

向量量化。

我们将向量量化称为将高维向量转换为低维码字元组的过程。最直接的技术之一是使用分层聚类，例如 [34] 中使用的技术，其中在某一迭代中创建的簇在下一迭代中被进一步划分为子簇。另一种流行的替代方法是向量量化变分自编码器（VQ-VAE），它在 [35] 中被提出，作为一种将自然图像编码为码序列的方法。该技术的工作原理是首先将输入向量（或图像）通过一个降低维度的编码器。较小维度的向量被划分，每个划分被单独量化，从而产生一个码序列：每个划分一个码。这些码随后被解码器用于重建原始向量（或图像）。

RQ-VAE [40, 21] 对 VQ-VAE 编码器的输出应用残差量化，以实现更低的重建误差。我们在第 3.1 小节中更详细地讨论该技术。 局部敏感哈希（LSH）[14, 13] 是一种用于聚类和近似最近邻搜索的流行技术。 我们在本文中用于聚类的特定版本是 SimHash [2]，它使用随机超平面来创建二进制向量，作为物品的哈希值。 由于其计算复杂度低且具有可扩展性 [13]，我们将其用作向量量化的基线技术。

Appendix B 基线

下面我们简要描述与 TIGER 进行比较的每个基线

  • •

    GRU4Rec [11] 是第一个基于 RNN 的方法，它使用定制的 GRU 来完成序列推荐任务。

  • •

    Caser [33] 使用 CNN 架构，通过应用水平和垂直卷积操作来捕获高阶马尔可夫链，以用于序列推荐。

  • •

    HGN [25]：分层门控网络通过一种新的门控架构捕获用户的长期和短期兴趣。

  • •

    SASRec [17]：自注意力序列推荐使用带因果掩码的 Transformer 对用户的序列交互进行建模。

  • •

    BERT4Rec [32]：BERT4Rec 通过使用双向自注意力 Transformer 完成推荐任务，解决了单向架构的局限性。

  • •

    FDSA [42]：特征级深层自注意力网络在 Transformers 中除物品嵌入外还将物品特征纳入输入序列。

  • •

    S3-Rec [44]：用于序列推荐的自监督学习提出在自监督任务上预训练双向 Transformer，以改进序列推荐。

  • •

    P5 [8]：P5 是一种近期方法，它使用预训练的大语言模型（LLM）将不同的推荐任务统一到单个模型中。

Appendix C 数据集统计

我们使用 Amazon Product Reviews 数据集 [10] 中的三个公开基准，该数据集包含 1996 年 5 月至 2014 年 7 月的用户评论和物品元数据。我们使用 Amazon Product Reviews 数据集的三个类别来完成序列推荐任务：“Beauty”、“Sports and Outdoors”和“Toys and Games”。表 6 总结了这些数据集的统计信息。我们使用用户的评论历史来创建按时间戳排序的物品序列，并过滤掉评论数少于 5 条的用户。遵循标准评估协议 [17, 8]，我们使用留一法策略进行评估。对于每个物品序列，最后一项用于测试，倒数第二项用于验证，其余用于训练。在训练期间，我们将用户历史中的物品数量限制为 20。

Appendix D 对 P5 数据预处理的修改

P5 源代码 33 3 https://github.com/jeykigung/P5 对 Amazon 数据集进行预处理，首先为每个用户创建会话，其中包含该用户评论过的按时间顺序排列的物品列表。在创建这些会话之后，数据集中的原始物品 ID 被重新映射为整数 1,2,3,…1,2,3,\dots 44 4 https://github.com/jeykigung/P5/blob/0aaa3fd8366bb6e708c8b70708291f2b0ae90c82/preprocess/data_preprocess_amazon.ipynb。 因此，第一个会话中的第一个物品得到的 id 为‘1’，第二个物品（如果之前未出现过）得到的 id 为‘2’，依此类推。值得注意的是，这种预处理方案是在创建训练集和测试集划分之前应用的。这导致生成的序列数据集中许多序列具有 a,a+1,a+2,…a,a+1,a+2,\dots 的形式。鉴于 P5 使用 Sentence Piece 分词器 [30]（见第 4.1 节，出处为 [8]），用户会话中的测试物品和训练物品可能共享子词，并可能在推理期间导致信息泄漏。

为解决泄漏问题，我们没有为物品分配递增的整数 id，而是分配随机整数 ID，然后创建用于训练和评估的划分。P5 的其余代码与论文中提供的源代码保持完全相同。 该数据集的结果在表 7 中作为‘P5’行报告。我们还从头实现了一个自己的 P5 版本，并且仅在序列推荐任务上训练该模型。我们的实现结果标记为‘P5-ours’。在我们的 P5 实现中，我们还能够验证：对物品 ID 使用连续整数序列有助于我们获得与 P5 中报告的指标相当或更好的指标。

Appendix E 讨论

语义 ID 长度和码本大小的影响。 我们尝试改变语义 ID 长度和码本大小，例如使用由 66 个码字组成的 ID，每个码字来自大小为 6464 的码本。我们注意到 TIGER 的推荐指标对这些变化具有鲁棒性。然而，请注意，输入序列长度会随着 ID 变长（即每个物品 ID 的码字更多）而增加，这会使我们基于 transformer 的序列到序列模型的计算代价更高。

可扩展性。 为了测试语义 ID 的可扩展性，我们运行了以下实验：我们将所有三个数据集合并，并为来自三个数据集的整个物品集合生成语义 ID。然后，我们在 Beauty 数据集上的推荐任务中使用这些语义 ID。我们将该实验的结果与仅从 Beauty 数据集生成语义 ID 的原始实验进行比较。结果见表 10。我们看到这里性能仅有小幅下降。

推理成本。 尽管我们的模型在序列推荐任务上取得了显著成功，但我们注意到，由于使用束搜索进行自回归解码，我们的模型在推理期间可能比基于 ANN 的模型计算代价更高。 我们强调，优化 TIGER 的计算效率并非这项工作的主要目标。 相反，我们的工作开辟了一个新的研究领域：基于生成式召回的推荐系统。 作为未来工作的一部分，我们将考虑使模型更小或探索其他提高推理效率的方法。

查找表的内存成本。 我们为 TIGER 维护两个查找哈希表：一个物品 ID 到语义 ID 表，以及一个语义 ID 到物品 ID 表。请注意，这两个表都只生成一次，然后被冻结：它们在基于 RQ-VAE 的语义 ID 生成模型训练之后生成，之后在序列到序列 transformer 模型的训练中保持冻结。 每个语义 ID 由 4 个整数的元组组成，每个整数存储在 8 位中，因此每个物品总共为 32 位。 每个物品由一个物品 ID 表示，存储为 32 位整数。 因此，每个查找表的大小将为 64⁢N64N 位的量级，其中 NN 是数据集中的物品数量。

嵌入表的存储开销。与传统推荐系统相比，TIGER使用的嵌入表要小得多。这是因为传统推荐系统为每个物品存储一个嵌入，而TIGER仅为每个语义码字存储一个嵌入。在我们的实验中，我们使用4个码字，每个码字的基数为256，用于Semantic ID表示，从而产生1024（256×\times4）个嵌入。对于传统推荐系统，嵌入的数量为NN，其中NN是数据集中的物品数量。在我们的实验中，NN的范围从10K到20K，具体取决于数据集。因此，TIGER嵌入表的存储开销为1024⁢d1024d，其中dd是嵌入的维度，而传统推荐系统中嵌入查找表的存储开销为N⁢dNd。
