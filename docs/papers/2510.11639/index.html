摘要

大语言模型（LLM）强大的生成能力推动了推荐领域范式的转变。然而，现有的生成式模型（如 OneRec）作为隐式预测器运行，严重缺乏显式、可控推理的能力——而这正是 LLM 的关键优势。为弥合这一差距，我们提出 OneRec-Think，一个无缝集成对话、推理和个性化推荐的统一框架。OneRec-Think 包含：(1) 物品级对齐：用于语义锚定的跨模态物品-文本对齐；(2) 推理激活：在推荐语境中激活 LLM 推理的推理脚手架；以及 (3) 推理增强，其中我们设计了一个考虑用户偏好多重有效性特性的推荐专用奖励函数。在多个公开基准上的实验展示了最先进的性能。此外，我们提出的“Think-Ahead”架构使模型能够在快手进行有效的工业部署，在 APP 停留时长上取得 0.159% 的增益，并验证了模型显式推理能力的实际效能。

1 引言

大语言模型（LLM）的快速发展从根本上重塑了推荐系统，催生了生成式检索范式（GR）(Peng et al., 2025; Zhang et al., 2025b; Deldjoo et al., 2024; Li et al., 2023; Wang et al., 2023)。该方法代表了对传统查询-候选项匹配的深刻转变，利用基于 Transformer 的序列到序列模型自回归地解码目标候选项的标识符。借此，一个主要的研究前沿是端到端生成式框架的开发，包括 OneRec、OneLoc、OneSug 和 OneSearch (Deng et al., 2025; Zhou et al., 2025a, b; Wei et al., 2025; Guo et al., 2025b; Chen et al., 2025)。这些统一模型取代了传统的多阶段推荐漏斗（涉及独立的召回和排序阶段），能够面向最终目标进行整体优化，并集中计算资源以实现更好的工业规模化和性能。

尽管这些模型成功利用了 LLM 的输出生成能力，但它们从根本上缺乏现代 LLM 突破所定义的显式、可验证的推理路径，例如基于文本的思维链（CoT）(Rajput et al., 2023; Zheng et al., 2024; Wang et al., 2024b)。 为弥合这一关键差距，我们提出 OneRec-Think，一个在单一统一模型中将对话、推理和个性化生成式推荐整合在一起的新颖框架。它能够生成高质量、可解释的文本推理路径，显著提升推荐准确性和用户可信度。该模型固有的对话特性进一步使建议能够针对特定的用户约束进行动态定制（如图 1 所示）。 我们的方法通过一个三阶段框架实现： (1) 物品级对齐，将物品语义映射到 LLM 的文本嵌入空间，建立统一的表示连续统，从而释放模型的推理能力。 (2) 推理激活，旨在直接在推荐系统的语境中诱导 LLM 固有的推理能力； (3) 推理增强，利用一个推荐专用的奖励函数，捕捉用户偏好的多重有效性（即多个有效选择）特性。此外，我们引入了 OneRec-Think 推理架构，以确保在工业级服务场景中的高效部署和实时响应能力。 我们的贡献总结如下：

  • •

    我们引入了一个统一框架，弥合了离散推荐物品与连续推理空间之间的语义差距，使个性化推荐能够无缝集成到 LLM 的自然语言理解中。

  • •

    我们设计了一种新颖的推理范式，将多步推敲与推荐优化协同编排，通过协同训练实现可解释且准确感知的个性化推荐。

  • •

    所提出的方法在多个公开基准上取得了最先进的结果，而我们便于部署的“Think-Ahead”架构在 APP 停留时长上取得 0.159% 的增益，带来了显著的工业影响。

2 相关工作

2.1 大语言模型中的推理

大语言模型通过各种提示技术实现复杂推理，其中 CoT 提示(Wei et al., 2022)是基础性方法，它将问题分解为中间推理步骤。 这启发了众多扩展，包括零样本 CoT (Kojima et al., 2022)、自一致性解码(Wang et al., 2022)和思维树(Yao et al., 2023)。 这些技术实现了测试时扩展，即在推理期间增加计算预算可提升性能(Snell et al., 2024)。 近期工作已从提示转向通过使用强化学习等技术对推理能力进行后训练增强。 包括 DeepSeek-R1 (Guo et al., 2025a) 和 Seed-1.5 (Seed et al., 2025) 在内的模型通过 GRPO (Shao et al., 2024)、DAPO (Yu et al., 2025) 和 VAPO (Yue et al., 2025) 等技术优化推理行为，这展示了该方向上有前景的进展。

2.2 基于推理的推荐

尽管 TIGER (Rajput et al., 2023)、HSTU (Zhai et al., 2024) 和 OneRec (Zhou et al., 2025a) 等生成式推荐模型已展示出有效性，但它们本质上缺乏推理能力。 近来，基于推理的推荐系统旨在执行多步推演，以实现更准确、更可解释的推荐。 现有方法分为两类：显式推理方法生成人类可读的理由，但局限于判别式任务(Tsai et al., 2024; Bismay et al., 2024; Fang et al., 2025; Kim et al., )；而隐式推理方法(Zhang et al., 2025a; Tang et al., 2025)执行潜在推理，不具备文本可解释性。 我们的工作将显式推理引入生成式推荐，弥合这一差距，从而同时实现可解释的理由和可扩展的物品生成。

3 预备知识

物品级 Token

物品级 token 是物品的离散、语义丰富的表示单元，类似于自然语言中的词 token。 遵循 OneRec (Zhou et al., 2025a; Rajput et al., 2023)，我们将每个物品 vv 映射为这样一系列 token 𝒔v=(sv1,…,svL)\bm{s}_{v}=(s_{v}^{1},\dots,s_{v}^{L})，它们由物品的多模态和协同内容生成。

问题定义

令 𝒰\mathcal{U} 和 𝒱\mathcal{V} 分别表示用户集和物品集。每个用户 u∈𝒰u\in\mathcal{U} 具有按时间排列的交互历史 Vu=(v1u,v2u,…,vnuu)V_{u}=(v^{u}_{1},v^{u}_{2},\dots,v^{u}_{n_{u}})，其长度为 nun_{u}。 为简洁起见，我们省略用户索引 uu。 通过使用物品级 token，用户的交互历史由此表示为序列 Su=(𝒔v1,…,𝒔vn)S_{u}=(\bm{s}_{v_{1}},\dots,\bm{s}_{v_{n}})。

传统生成式推荐器(Rajput et al., 2023; Zhou et al., 2025a, b; Zheng et al., 2024)将其任务的生成目标定义为下一个物品级 token：

𝒔vn+1∼P(⋅|𝒔v1,…,𝒔vn;θ)\bm{s}_{v_{n+1}}\sim P(\cdot|\bm{s}_{v_{1}},\dots,\bm{s}_{v_{n}};\theta) (1)

相比之下，我们重新表述该任务，以在单次自回归过程中统一推理和推荐。以提示的用户历史为条件，我们按顺序生成 token，从推理序列 𝝉=(r1,…,rM)\bm{\tau}=(r_{1},\dots,r_{M}) 开始，并以下一个物品级 token 𝒔vn+1\bm{s}_{v_{n+1}} 结束。这一端到端过程可表示为：

𝝉\displaystyle\bm{\tau} ∼P(⋅∣𝒫(𝒔v1,…,𝒔vn);θ)\displaystyle\sim P\left(\cdot\mid\mathcal{P}(\bm{s}_{v_{1}},\dots,\bm{s}_{v_{% n}});\theta\right) (2)
𝒔vn+1\displaystyle\bm{s}_{v_{n+1}} ∼P(⋅∣𝒫(𝒔v1,…,𝒔vn),𝝉;θ)\displaystyle\sim P\left(\cdot\mid\mathcal{P}(\bm{s}_{v_{1}},\dots,\bm{s}_{v_{% n}}),\bm{\tau};\theta\right)

其中 𝒫⁢(⋅)\mathcal{P}(\cdot) 表示为推荐构造的有效提示。

4 方法

我们现在介绍 OneRec-Think，一个用于端到端生成式推理推荐的可扩展框架。我们的方法包含三个核心组件：物品级对齐阶段、推理激活阶段，以及用于工业部署的“Think Ahead”架构。 OneRec-Think 的示意图如图 2 所示。

4.1 通过多任务预训练实现物品级对齐

为使推荐知识与大语言模型的语言空间对齐，我们设计了多任务预训练策略，通过下一 token 预测下的四个互补任务，实现对自然语言和物品级 token 的无缝处理。

交错用户画像语义锚定

不同于先前使用纯文本数据或孤立物品序列的工作，该任务将用户画像的物品级 token 和文本 token 交错在一起。 它包括序列化的静态属性、主动搜索行为、交互序列以及总结的用户兴趣。 这种组合创建了丰富的双模态训练实例，其中物品级 token 扎根于其语义语境中。

序列偏好建模

作为核心推荐任务，该任务构建数据，教导模型根据时间顺序的用户历史预测后续物品交互。

物品级稠密描述

该任务要求模型从其物品级 token 解码物品的描述性内容。 通过学习生成详细的文本描述，模型建立起对物品组合所代表语义特征的基本理解。

通用语言建模

该任务在通用文本语料上继续预训练模型，在将模型应用于推荐场景时保留其基础语言能力。

为实现有效的知识整合，同时保留模型的语言能力，我们采用两子阶段训练策略以确保稳定对齐。 Token 预热子阶段仅在交错用户画像语义锚定任务上训练物品级 token 嵌入，同时保持基础 LLM 冻结。 随后的多任务整合子阶段使用设计的比例在组合任务上联合优化所有参数（详见附录 A.3）。

4.2 推理激活

尽管物品级对齐稳健，但由于真实世界用户行为序列的噪声性和冗长性，直接应用于工业推荐场景往往无法产生有效的 CoT 推理。 为解决此问题，我们提出一个监督微调框架，首先从剪枝后的用户上下文中提取连贯的推理轨迹，然后利用这些轨迹引导在原始行为数据上生成理由，从而为噪声工业环境实现有效的上下文蒸馏（如图 2(b) 所示）。

以剪枝上下文进行引导： 为引导推理能力，我们首先构建易于学习的实例，其中尽管序列被剪枝，逻辑关系仍得以保留。对于每个用户，我们选择目标物品 𝒔vn+1\bm{s}_{v_{n+1}} 并形成上下文-目标对 <(𝒔v1,…,𝒔vn),𝒔vn+1><(\bm{s}_{v_{1}},\dots,\bm{s}_{v_{n}}),\bm{s}_{v_{n+1}}>。然后，我们检索 top-kk 最相关的历史物品，所用相似度函数为 g⁢(⋅,⋅)g(\cdot,\cdot)：

g⁢((𝒔v1,…,𝒔vn),𝒔vn+1)=(𝒔w1,…,𝒔wk).g((\bm{s}_{v_{1}},\dots,\bm{s}_{v_{n}}),\bm{s}_{v_{n+1}})=(\bm{s}_{w_{1}},% \dots,\bm{s}_{w_{k}}). (3)

使用这些相关物品，我们查询预对齐模型以生成解释目标交互的理由 𝝉\bm{\tau}：

𝝉\displaystyle\bm{\tau} ∼P(⋅∣𝒫r((𝒔w1,…,𝒔wk),𝒔vn+1);θ)\displaystyle\sim P\left(\cdot\mid\mathcal{P}_{r}((\bm{s}_{w_{1}},\dots,\bm{s}% _{w_{k}}),\bm{s}_{v_{n+1}});\theta\right) (4)

其中 𝒫r⁢(a,b)\mathcal{P}_{r}(a,b) 表示构造一个提示，以查询与物品序列 aa 交互的用户为何会与物品 bb 交互的理由。 该过程产生既逻辑合理又与目标对齐的高质量理由，为推理诱导提供了理想的训练信号。

从噪声序列中学习推理： 蒸馏出的理由作为从原始序列学习推理的监督信号。 训练目标最小化生成理由和目标物品的负对数似然：

ℒRA=−(∑i=1MlogP(ri|𝒫(𝒔v1,…,𝒔vn),r<i;θ)\displaystyle\mathcal{L}_{\text{RA}}=-\Biggl{(}\sum_{i=1}^{M}\log P(r_{i}|% \mathcal{P}(\bm{s}_{v_{1}},\dots,\bm{s}_{v_{n}}),r_{<i};\theta) (5)
+∑j=1LlogP(svn+1j|𝒫(𝒔v1,…,𝒔vn),𝝉,svn+1<j;θ)),\displaystyle+\sum_{j=1}^{L}\log P(s_{v_{n+1}}^{j}|\mathcal{P}(\bm{s}_{v_{1}},% \dots,\bm{s}_{v_{n}}),\bm{\tau},{s}_{v_{n+1}}^{<j};\theta)\Biggr{)},

其中 𝝉={r1,…,rM}\bm{\tau}=\{r_{1},\dots,r_{M}\} 表示理由 token，𝒔vn+1={svn+11,…,svn+1L}\bm{s}_{v_{n+1}}=\{s_{v_{n+1}}^{1},\dots,s_{v_{n+1}}^{L}\} 表示目标物品 token。 通过优化 ℒRA\mathcal{L}_{\text{RA}}，模型学会从噪声序列中内部蒸馏相关上下文，并生成连贯的理由，将用户历史与目标交互连接起来，从而显著增强其在具有挑战性的推荐场景中的 CoT 能力。

4.3 推理增强

在推理激活所获 CoT 能力的基础上，我们通过强化学习解决确保始终如一的高质量推理这一挑战。 该阶段使用为生成式推荐量身定制的新颖奖励机制来精炼推荐准确性。

束候选奖励最大化： 标准的可验证通过奖励在推荐场景中面临显著的稀疏性挑战，因为大多数推演路径未能命中目标物品，因而产生相同的零奖励——从而使 GRPO 等算法中的组优势失效(Shao et al., 2024)。 为克服这一问题，我们引入了推演-束奖励，它通过模型在受限束内可达到的最佳性能来评估推理能力。 我们的方法采用宽度为KK的束搜索，在推理轨迹生成之后探索多个生成候选：

ℛRollout-Beam=maxs^vn+1∈ℬ⁢∑l=1L𝕀⁢(s^vn+1l=svn+1l),\mathcal{R}_{\text{Rollout-Beam}}=\max_{\hat{s}_{v_{n+1}}\in\mathcal{B}}\sum_{% l=1}^{L}\mathbb{I}(\hat{s}_{v_{n+1}}^{l}=s_{v_{n+1}}^{l}), (6)

其中束搜索的结果集定义为：

ℬ={(s^vn+11,(j),⋯,s^vn+1L,(j))j=1K},=BeamSearch⁢(P⁢(𝒔vn+1∣𝑯,𝝉;θ),K)\begin{split}\mathcal{B}&=\bigl{\{}\bigl{(}\hat{s}_{v_{n+1}}^{1,(j)},\cdots,% \hat{s}_{v_{n+1}}^{L,(j)}\bigr{)}_{j=1}^{K}\bigr{\}},\\ &=\text{BeamSearch}\Bigl{(}P(\bm{s}_{v_{n+1}}\mid\bm{H},\bm{\tau};\theta\bigr{% )},K\Bigr{)}\end{split} (7)

它包含束搜索中概率排名前KK的物品，搜索在分布P⁢(𝒔vn+1∣𝑯,𝝉;θ)P\left(\bm{s}_{v_{n+1}}\mid\bm{H},\bm{\tau};\theta\right)内进行。 𝑯=𝒫⁢(𝒔v1,…,𝒔vn)\bm{H}=\mathcal{P}(\bm{s}_{v_{1}},\dots,\bm{s}_{v_{n}})是历史序列的一个有效提示。 BeamSearch⁢(P,K)\text{BeamSearch}(P,K)表示束搜索的前KK结果，搜索在分布PP内进行。 随后，我们使用 GRPO(Shao et al., 2024)基于ℛRollout-Beam\mathcal{R}_{\text{Rollout-Beam}}优化模型，该方式有效利用了来自用户偏好多有效性本质的丰富奖励信号。

总体而言，该设计通过将奖励计算与基于束搜索的推理对齐，建立了训练-推理一致性，并通过多路径评估提供了更密集的学习信号。

4.4 工业部署：“提前思考”架构

OneRec-Think 在工业推荐系统中的应用提出了一个根本性挑战：如何调和多步推理的计算需求与实时用户交互的严格延迟要求。

为解决这一关键瓶颈，我们引入了一种新颖的提前思考推理架构。我们的方案策略性地将模型推理解耦为两个阶段：在第一阶段，计算密集的推理路径和初始物品词元（例如前两个物品词元）由完整的 OneRec-Think 模型离线生成。这些初始词元旨在捕捉用户的广泛意图或一般偏好上下文。随后，第二阶段采用实时更新的 OneRec 模型，遵循Zhou et al. (2025a)进行在线最终确定。它以预生成的物品词元作为受限前缀，快速生成最终的物品词元。该设计确保了实时响应性，并通过利用当前上下文数据实现生产级性能。 该架构的细节见附录A.3.4。

6 结论

我们提出了 OneRec-Think，一个通过三项关键创新将推理能力与生成式推荐相连接的新颖框架：层次化物品词元对齐、通过 CoT 监督微调的推理激活，以及基于强化学习的推理精炼。 我们的方法从根本上将推荐系统从单纯的物品预测器转变为具有推理意识的模型，在提供高质量推荐的同时生成可解释的理由。 大量实验表明，OneRec-Think 不仅在多个基准上达到最先进性能，还转化为具体的工业影响，在 APP 停留时长等主要指标上取得0.15%的增益。 未来工作将聚焦于探索用户长序列建模和用于更细粒度偏好建模的密集 RL 奖励，进一步弥合基于 LLM 的推理与工业推荐系统之间的差距。

局限性

尽管经验结果令人鼓舞，当前公开数据集因其有限的行为序列长度和受限的物品空间而存在质量约束。 这些局限阻碍了我们的推理激活和推理增强模块获得可与从工业规模数据中学到的相媲美的高质量推理能力。 因此，我们简化并调整我们的方法，以实现稳定但简化的推理能力，这在公开数据集内仍然稳健。 为解决这些问题，我们正在积极构建一个具有扩展行为轨迹和多样化物品目录的大规模基准，这将能够对基于推理的推荐模型的推理能力进行更全面的评估。

伦理声明

在本工作中，我们针对两种设置进行了实验：一种针对开源基准数据集，一种针对工业场景。 对于开源基准数据集的实验，所有数据集均可从先前工作或公共 API 公开获得，同时保持匿名性。 对于工业场景，我们利用从我们的平台收集的用户交互数据来训练推荐模型。 所有数据收集和使用严格遵循我们平台的隐私政策和服务条款，用户已对此提供明确同意。 重要的是，我们的训练过程仅基于聚合的行为序列、文本内容和用户基础信息运行，不访问或处理任何个人可识别信息。

A.1 实验设置

基线细节

我们在两组工作中将 OneRec-Think 与有竞争力的基线进行比较，即传统推荐模型和生成式推荐模型： 1) BERT4Rec (Sun et al., 2019) 利用 BERT 的预训练语言表示来捕捉语义层面的用户-物品关系。 2) HGN (Ma et al., 2019) 利用图神经网络学习用户和物品表示，以预测用户-物品交互。 3) GRU4Rec (Hidasi et al., 2016) 是一个轻量级图卷积网络模型，专注于用户与物品之间的高阶连接。 4) SASRec (Kang and McAuley, 2018) 采用自注意力机制来捕捉用户交互历史中的长期依赖关系。 5) TIGER (Rajput et al., 2023) 通过 RQ-VAE 引入基于码本的标识符，将语义信息量化为码序列，用于基于 LLM 的生成式推荐。 6) HSTU (Zhai et al., 2024) 在生成式建模框架内将推荐问题重构为序列转导任务，并提出了一种面向流数据的新架构。 7) ReaRec (Tang et al., 2025) 在面向推荐的推理时计算框架内，通过隐式多步推理增强用户表示。 评估指标。 我们使用两个指标：top-KK Recall（R@KK）和 NDCG（N@KK），其中 KK = 5 和 10，遵循 Rajput et al. (2023)。

开源数据集上的实验细节

我们采用 Qwen3-1.7B (Yang et al., 2025) 作为骨干模型。 模型的词表扩展了 1,024 个新 token，表示四级层次化语义 ID（每级 256 个 token），此外还增加了两个特殊边界 token：<|item_begin|> 和 <|item_end|>。 所有模型均在配备旗舰 GPU 的服务器上训练。 为在评估期间生成 top-K 推荐，我们采用束搜索策略，束宽为 10。 鉴于从公开基准中典型的短且稀疏的物品序列推导出稳健的推理路径 𝝉\bm{\tau} 存在固有挑战，我们策略性地采用人工构建的基于类别的 CoT 作为 Reasoning Activation 的剪枝内容，以确保稳定的语义引导。 对于训练数据，我们采用先前工作 (Rajput et al., 2023; Wang et al., 2024a) 中的预处理技术，丢弃交互数少于 5 的稀疏用户和物品。 我们考虑序列推荐设置，并使用 留一法策略 (Rajput et al., 2023; Zheng et al., 2024) 来划分数据集。 对于训练，我们遵循 (Kang and McAuley, 2018) 将用户历史中的物品数量限制为 50。

4. 通用语言建模。 这部分数据包含通用语料的预训练和指令微调数据，以维持语言模型的基础能力。

为使模型能够进行文本内推理推荐，我们设计了一个两阶段训练课程，首先建立基础语义理解，然后发展复杂的推荐能力。 初始子阶段 Token Warm-up 专注于将 itemic token 与其丰富的文本含义对齐。 第二个子阶段 Multi-Task Integration 在保持初始语义对齐的同时，发展模型的核心推荐能力。

Token Warm-up

初始且基础的步骤是让模型深入理解每个 itemic token（𝒔v\bm{s}_{v}）所表示的语义内容。 在开源基准数据集中，数据集由完整训练数据的用户画像组成。 在工业场景中，整个对齐过程利用 Interleaved User Persona Grounding 任务的 6 十亿 token 语料，确保全面的语义锚定。

在此阶段，我们冻结 LLM 骨干的参数，仅训练新引入的 itemic token 的嵌入。 这种聚焦式方法使随机初始化的嵌入能够高效收敛到模型现有语义空间中的有意义位置，而不会破坏其预训练知识。 我们使用较高的学习率 5×10−45\times 10^{-4} 仅训练新 token 嵌入，使随机初始化的嵌入能够快速高效地收敛。

Multi-Task Integration

在语义物品词表成功锚定后，课程的第二子阶段旨在发展模型的核心推荐能力。 仅对单一目标（如下一物品预测）进行训练，可能导致模型逐渐将 itemic token 视为常规的非语义标识符，从而失去初始锚定子阶段的益处。 为防止这种情况并促进更全面的理解，我们采用 Multi-Task Integration。 不同任务的混合（详见表 5）旨在平衡协作模式的学习与语义理解和上下文推理的强化。

对于开源基准数据集，我们训练模型的全参数。 对于工业场景，我们解冻模型骨干并利用 LoRA (Hu et al., 2022) 进行参数高效微调。 我们采用更保守的学习率 3×10−43\times 10^{-4} 对模型进行微调，确保模型内部机制稳定适应推荐任务而不破坏其基础知识。
