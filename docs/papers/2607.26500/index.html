摘要

工业推荐系统通过为目标特定的召回路径分配显式配额来构建候选池。这种设计提供了配额控制，但随着路径集合增长，日益割裂建模、训练与 Serving。基于 Semantic-ID 的生成式检索提供了一种统一的替代方案，然而单个解码器会使目标策略相互纠缠，并限制候选的互补性。我们提出Multi-Decoder OneRec，这是一个结合共享表示、目标隔离适配与协同解码的可控框架。所有目标共享一个用户上下文模块和 General Decoder，同时每个目标增加一个隔离的、参数高效的 LoRA 专家。训练时，曝光样本的下一词元预测（NTP）更新共享基座，目标过滤的 NTP 更新基于事件的专家，Kullback–Leibler（KL）正则化的策略优化更新 Watch-time 专家；梯度路由隔离这些更新，并由 General Decoder 提供停止梯度的参考。推理时，显式路径配额分配固定预算，Multi-Decoder Constrained Beam Search 减少跨路径重叠。我们公开发布Kwai26，这是一个大规模多目标基准，包含1.31十亿条原始物品级记录、31.85百万条 Item-ID 条目、以及25.03百万个具有有效 Semantic ID 的物品，并附带预定义划分和评估协议。在相同的512物品召回预算下，相较于单解码器 OneRec (Deng et al., 2025)基线，Multi-Decoder OneRec 提升1.69%–5.62%，对应四项 Recall@512指标。在生产环境 A/B 测试中，其在每设备应用使用时长上取得0.37%的相对提升，取得0.19%的相对提升，指标为 Day-7留存用户数，在至少有一次分享的设备上取得0.19%的相对提升，在新内容冷启动上取得2.09%的相对提升。这些结果表明，生成式检索能够将共享建模与目标特定控制以及互补的候选生成结合起来。

1. 引言

大规模推荐系统中的候选召回必须在多个目标之间分配固定的候选预算(Covington et al., 2016; Huang et al., 2025)。工业系统为观看时长、显式交互和冷启动等目标组合众多专用召回路径(Xie et al., 2020; Nie et al., 2022)，并为每条路径分配可配置的预算份额(Huang et al., 2025; Zhou et al., 2026)。这种设计拓宽了覆盖范围，并直接控制候选构成。然而，扩展路径集合会割裂模型开发、训练与 Serving，同时增加计算与维护开销。这些局限性促使我们设计一种统一的召回器，在共享建模能力的同时不牺牲对候选构成的显式控制。

生成式检索通过将每个物品表示为离散的 Semantic ID 序列并生成候选，为这一目标提供了所需的共享建模(Rajput et al., 2023; Jin et al., 2024; Wang et al., 2024a; Liu et al., 2026b)。许多统一生成器使用单个解码器服务多个目标。由于所有目标使用相同的注意力层和前馈层，联合训练会将它们的生成策略耦合在一起。针对某一目标的更新会改变其他目标所使用的变换，当它们的监督信号和偏好的候选分布出现分歧时，这可能导致负迁移(Ma et al., 2018; Tang et al., 2020)。现有方法通过提示、任务词元或行为词元注入目标信息(Geng et al., 2022; Liu et al., 2024; Shi et al., 2025)。相关工作使用寄存器词元或依赖上下文的序列起始（BOS）查询(Yang et al., 2025; Liu et al., 2026a)。当用于目标区分时，这些机制只引入少量目标特定状态，主要位于输入或初始解码状态中。决定词元概率的核心变换仍然共享。因此，它们改变的是共同策略的条件方式，而不是为每个目标提供专用的可训练变换。目标策略在优化过程中仍然相互耦合。在推理时，分别以目标为条件的多次运行也可能偏向相同的高概率 Semantic ID 区域，并在固定预算下产生重叠的候选列表。图1的面板 (a) 和 (b) 总结了这一核心权衡。传统的多路径召回可控但割裂，而单解码器生成式检索统一但耦合。

解决这一权衡需要满足三项相互耦合的要求。第一，共享建模必须支持各目标的独立更新。复用用户表示和共同的 Semantic ID（SID）生成先验可以避免完整解码器的复制，但每个目标仍然需要足够的可训练容量，以便在不扰动通用策略或其他目标的情况下进行适配。为每个目标复制一个完整的解码器虽然能恢复独立性，却只会重新造成模型、训练和 Serving 的割裂。第二，优化必须适应异构反馈，同时保持生成的有效性。不同目标可能需要不同的样本构造和学习信号，但专门化必须保留从广泛曝光中学到的有效 SID 分布。第三，专门化策略必须贡献互补的候选。独立策略仍可能产生重叠的高概率候选，因此需要显式配额和协同搜索，以防止重叠浪费固定预算。因此，一个实用的框架必须在表示上共享、在目标特定更新上隔离、在解码上协同。

图1的面板 (c) 展示了我们的解决方案Multi-Decoder OneRec。(1) 共享但隔离的架构。一个共享的用户上下文模块提供可复用的用户表示，而 General Decoder 提供基础权重和共同的 SID 生成先验。每个目标附加一个隔离的专家，包含低秩适配（LoRA）(Hu et al., 2022)更新、目标特定的 BOS 嵌入，以及对共享 SID 嵌入表的加性偏移。专家与 General Decoder 一起构成目标特定的解码器。(2) 带梯度隔离的反馈自适应优化。General Decoder 和各目标专家从相互独立的监督流中并发训练，梯度路径不相交。曝光样本的 NTP 更新共享基座，而每个目标的损失只更新其对应的专家状态，梯度在共享基座参数处停止。基于事件的专家在目标过滤的样本上使用 NTP，而 Watch-time 专家使用带有按用户历史归一化的相对奖励的策略优化(Deng et al., 2025; Zhou et al., 2025b; Shao et al., 2024)。KL 正则化使用 General Decoder 的停止梯度分布作为参考，将 Watch-time 专家锚定到共同的 SID 先验，同时 General Decoder 继续从曝光样本中学习。(3) 配额感知的协同解码。Multi-Decoder Constrained Beam Search（MD-CBS）为每个目标特定解码器分配显式配额，并在可配置的解码层级上屏蔽先前路径已占据的 SID 前缀(Vijayakumar et al., 2018; Anderson et al., 2017; Post and Vilar, 2018)。约束层级决定是排除精确 SID 还是更宽泛的语义区域。General Decoder 最后运行，并用先前未被选中的合法候选回填任何剩余预算。

我们在离线和生产环境中评估 Multi-Decoder OneRec。为了可复现的离线评估，我们公开发布Kwai26，这是一个面向多目标生成式检索的大规模基准，包含1.31十亿条原始物品级记录、31.85百万条 Item-ID 条目、以及25.03百万个具有有效 Semantic ID 的物品。在相同的512物品召回预算下，Multi-Decoder OneRec 取得1.69%–5.62%的相对提升，其比较对象为单解码器 OneRec (Deng et al., 2025)基线，对应四项 Recall@512指标。在生产环境 A/B 测试中，其在每设备应用使用时长上取得0.37%的相对提升，取得0.19%的相对提升，指标为 Day-7留存用户数，在至少有一次分享的设备上取得0.19%的相对提升，在冷启动上取得2.09%的相对提升。离线与在线结果共同表明，Multi-Decoder OneRec 在不牺牲通用曝光召回的前提下改进了专门化目标，并且这些收益转化为可衡量的生产价值。我们的主要贡献如下：

  • •

    据我们所知，Multi-Decoder OneRec是首个在固定候选预算下为共享 SID 召回器配备目标特定解码器、梯度隔离适配、显式逐路径配额以及跨解码器约束搜索的框架。

  • •

    我们提出了具有隔离梯度路径的专家优化方法和 Multi-Decoder Constrained Beam Search（MD-CBS）。对目标过滤样本的 NTP 和带相对奖励的策略优化分别处理基于事件的反馈和连续反馈，而参考正则化保留通用的 SID 先验。MD-CBS 将显式路径配额与跨路径前缀约束相结合，以减少重叠并提升候选互补性。

  • •

    我们公开发布Kwai26，这是一个面向多目标生成式检索的十亿规模基准，并附带预定义划分和评估协议。大量离线实验和生产环境 A/B 测试在工业规模上验证了 Multi-Decoder OneRec。

2. 相关工作

2.1. 生成式推荐

Semantic ID 建模。生成式检索生成 Semantic ID（SID）序列，而不像 SASRec (Kang and McAuley, 2018)和 BERT4Rec (Sun et al., 2019)那样对固定目录进行打分。TIGER (Rajput et al., 2023)引入了层次化 SID；后续工作探索了自监督(Jin et al., 2024)、多信号学习(Wang et al., 2024a)、上下文分词或表示(Hou et al., 2025b; Liu et al., 2026a)，以及分词器–推荐器联合优化(Bai et al., 2026)。RPG (Hou et al., 2025a)和 DiffGRM (Liu et al., 2026b)分别通过并行生成和离散扩散改进解码。这些方法聚焦于单一生成器，而不是固定预算下梯度隔离的目标策略。

偏好对齐。标准 NTP 不编码分级反馈或下游效用。OneRec (Deng et al., 2025; Zhou et al., 2025a)和 OneRec-V2 (Zhou et al., 2025b)引入了迭代对齐、时长感知奖励和基于组的优化。GenRec (Zou et al., 2026)结合了页面级 NTP、GRPO-SR 和混合奖励；GFlowGR (Wang et al., 2026)优化生成轨迹；UGR (Fan et al., 2026)对奖励不确定性建模。这些方法通常对齐单一策略，尚未探索跨并发目标的隔离更新。

2.2. 多目标召回

目标特定适配。P5 (Geng et al., 2022)、MBGen (Liu et al., 2024)和 GenSAR (Shi et al., 2025)用提示或行为词元对共享生成器进行条件化，但不提供目标特定的变换或梯度隔离。PinRec (Botta et al., 2026)将统一模型以界面特定结果为条件，而 EAGER (Wang et al., 2024b)将行为词元流与语义词元流分离。MMoE (Ma et al., 2018)和 PLE (Tang et al., 2020)为共享–特定分解提供了依据，LoRA (Hu et al., 2022)实现了参数高效的适配。

配额感知解码。多路径召回研究路径融合和触发选择(Xie et al., 2020; Nie et al., 2022; Huang et al., 2025; Zhou et al., 2026)，通过路径特定模型或 Serving 逻辑保留配额控制。多样化束搜索(Vijayakumar et al., 2018)使单个解码器多样化，而约束解码(Anderson et al., 2017; Post and Vilar, 2018)限制词元或前缀；两者在生成式检索中均面临已知局限(Wu et al., 2025)。先前工作未能在同一 SID 空间内跨目标特定生成器协调配额。Multi-Decoder OneRec 结合了共享 SID 先验、隔离适配和配额感知的跨路径解码。

4. Multi-Decoder OneRec

如图2所示，Multi-Decoder OneRec在共享的OneRec风格编码器–解码器主干(Deng et al., 2025; Zhou et al., 2025a)上构建多个目标特定解码器。它包含一个用户上下文模块、一个完全参数化的General Decoder以及MM个目标特定解码器。General Decoder学习通用曝光召回，并提供公共的SID生成先验。目标LoRA专家tt复用基础权重，仅添加任务BOS嵌入、SID嵌入残差和LoRA参数。共享参数捕获可迁移的用户兴趣与SID语法。隔离的任务参数支持梯度隔离的目标更新。协同解码在固定预算下将策略差异转化为互补候选。在并发优化过程中，曝光损失更新共享的用户上下文模块和General Decoder。每个目标损失在这些共享参数处停止，仅更新其对应的专家，使其他所有专家保持不变。

4.1. 用户上下文预填充

如图2(a)所示，在编码器一侧，每个请求由两个时间截断的行为视图表示：用户历史序列中最近交互的20个视频和256个Long-View视频。该设计使模型能够在执行任何目标特定解码之前联合捕获短期意图和长期偏好。对于每个视频，我们构建一个五字段特征元组，即：Item-ID、作者ID、标签、时间差和观看时长。这些字段首先映射为嵌入，然后由四块编码器处理。每个编码器块包含特征级交叉注意力和序列级自注意力。交叉注意力子层融合异构物品特征，而自注意力子层建模用户行为序列内部的依赖关系。经过堆叠编码后，模型获得用户上下文状态𝐇u=Enc⁡(Huτ)\mathbf{H}_{u}=\operatorname{Enc}(H_{u}^{\tau})，该状态每个请求只计算一次，并作为所有解码器路由中交叉注意力模块的键和值被复用。

4.2. 多解码器

图2(a)还展示了共享的General Decoder及其轻量级目标特定分支。在解码器一侧，每个目标视频由一串离散Semantic ID（SID）表示。每个SID词元通过嵌入查找表映射为向量。训练期间，General Decoder的输入（Decoder0）由可学习的序列起始（BOS）嵌入与右移后的目标SID序列拼接而成。所得序列由堆叠的Transformer解码器块处理，每个块由掩码自注意力、交叉注意力和前馈网络（FFN）组成。掩码自注意力保持SID生成的自回归分解，交叉注意力注入编码后的用户兴趣上下文𝐇u\mathbf{H}_{u}，FFN则对词元表示进行进一步的非线性变换。

4.4. 多解码器约束束搜索

图2(c)展示了协同推理流程。独立解码后的事后去重会浪费束容量：不同解码器可能将各自配额花费在同一物品上，导致合并后的候选池低于名义召回预算。因此我们使用MD-CBS，即约束解码(Anderson et al., 2017; Post and Vilar, 2018)的多解码器变体。MD-CBS按预定义优先级顺序执行各解码器路径，并让每个后续路径避开已被先前路径占据的候选。每条路径被指定为(r,br,qr)(r,b_{r},q_{r})，其中rr为解码器路径，brb_{r}为其束大小，qrq_{r}为其输出配额。各配额之和等于最终召回预算BB，General Decoder被放在最后，以回填剩余的一般曝光槽位。

由于物品 SID 是层次化的，约束可以施加在任意从零开始的 SID 层级0≤d<L0\leq d<L上。令𝐳0:d=(z0,…,zd)\mathbf{z}_{0:d}=(z_{0},\ldots,z_{d})为对应的部分假设。MD-CBS 将其用作去重键。对于路径rr，令𝒦<r(d)\mathcal{K}^{(d)}_{<r}表示所有第dd级键，这些键由先前路径在顺序π\pi下接受，并令sr⁢(𝐳0:d)s_{r}(\mathbf{z}_{0:d})为其路径得分。掩蔽后的得分为：

路径rr跳过被掩蔽的候选，沿其束列表继续，直到接受qrq_{r}个唯一候选或其束耗尽。随后，在下一个路径开始之前，将已接受的键插入𝒦≤r(d)\mathcal{K}^{(d)}_{\leq r}。

约束层级控制质量–效率权衡。较小的dd会在更深扩展前移除已被占用的前缀，因此可降低解码成本，但也会收窄搜索广度：一旦较浅的前缀被占据，后续路径便无法在同一粗略语义区域内探索其他有用物品。较大的dd会推迟去重并保留更丰富的语义探索，但需要更多解码。在我们的默认设置中，每个物品SID有三个层级(z0,z1,z2)(z_{0},z_{1},z_{2})，我们设置d=2d=2，因此将完整的SID元组用作键。这既能防止完整SID重复，又不会过早排除粗粒度语义区域；由SID到物品碰撞造成的物品级重复在合并过程中被移除。更早层的约束在第5节中作为粒度变体进行评估。最后，General Decoder最多召回其配额数量的未见完整SID。这将独立训练的、面向不同目标的解码器，在固定预算BB下转换为配额受控、无重复的候选池。

4.5. 服务流程

在服务时，所有解码器共享同一份已物化的编码器表示。每个活跃解码器在约束合并之前应用其自己的BOS、SID残差、LoRA状态、束大小和配额。因此，目标集合和配额分配可以在不修改General Decoder或其他专家的情况下发生变化。每增加一个解码器仍会带来解码器计算开销，第5.5节将其与参数数量分开报告。

5.3. 消融研究

单解码器与多解码器训练。 表2将任务特定解码与配额控制的多解码器聚合分离开来。专门化解码器可以优化其自身目标：Long-View和Watch-time解码器取得最强的对应召回。然而，它们在其他方面各有损失，表明单一目标策略不能作为平衡的召回池。我们的方法将隔离更新与配额控制聚合相结合，是唯一在全部四项指标上均排名前二的配置。因此，仅有专门化并不足够：其价值在保留不同候选流并在共享预算下合并时才得以体现。这提供了比共享General Decoder或任何单一专门化策略更强的多目标工作点。此外，我们将所提方法与Multi-BOS基线进行比较，后者在相同训练协议和配额分配下将每个BOS词元分配给特定任务变体。结果表明，我们的方法在所有指标上均持续优于该变体。这表明仅靠任务特定的BOS信号不足以实现有效的目标专门化，而LoRA专家适配为学习任务对齐的生成模式提供了更具表现力的机制。

MD-CBS。 此处，CBS表示约束束搜索（Constrained Beam Search）。我们使用L2 CBS和L3 CBS分别表示MD-CBS在第二层和第三层SID上应用跨路径约束；No CBS表示无跨路径约束的独立解码。 不使用MD-CBS时，独立路径会反复生成相同物品；去重后平均仅剩207.67个唯一候选，且四项目标上的召回均为最低。L2 CBS和L3 CBS均恢复了完整的512个物品预算（表3），证实协同约束回收了原本因重叠而消耗的容量。L2会阻断被占用第二级前缀下的所有后续生成，因此后续路径无法在该粗粒度语义区域内探索不同物品。L3仅掩蔽完整SID。它在移除完全重复项的同时保留更多搜索广度，在所有目标上取得最佳召回，因此是默认工作点。由于L2 CBS和L3 CBS返回的候选数量相同，L3 CBS更高的召回不能由池大小解释；这表明将去重推迟到完整SID层面可避免过早剪除语义相关但不同的物品。

5.4. A/B测试

我们在Kwai Brazil的生成式推荐流水线上进行了为期七天的A/B测试。该生产流水线以生成式召回为核心，其召回的候选贡献了总曝光的57%，随后是排序和重排阶段。实验流量按设备标识符（DID）分配，DID作为随机化单元。对照组包含14.64%的DID，使用单解码器OneRec(Deng et al., 2025)。实验组包含7.32%的DID，保留相同的共享编码器和General Decoder，并增加具有明确路径配额的Watch-time、Share和Cold-Start解码器。除生成式召回模块外，两组使用相同的排序阶段。

在相同的下游技术栈下，核心产品指标——每设备使用时长——提升+0.37%，同时Day-1/7留存（+0.12%/+0.19%）、互动（+0.19%–+0.52%）和Cold-Start（+2.09%）也得到提升（表4）。十项结果涵盖留存、消费、互动和生态覆盖；附录D记录了共享报告范围和其余个人主页访问结果。

6. 结论

我们提出了 Multi-Decoder OneRec，用于可控多目标生成式召回。首先，它将共享的用户上下文模块和 General Decoder 与目标特定的解码器相结合。其次，其反馈自适应优化对基于事件的反馈使用目标过滤的 SFT，对观看时长解码器使用 KL 正则化的相对奖励策略优化，同时 MD-CBS 协调显式路径配额，在固定预算下产生互补候选。第三，我们发布了 Kwai26，包含预定义划分和评估协议，并在离线和生产环境中验证了该框架。在相同的512物品预算下，Multi-Decoder OneRec 在四个 Recall@512指标上提升1.69%–5.62%，其比较对象为单解码器 OneRec (Deng et al., 2025)；生产 A/B 测试进一步将每设备使用时长提升0.37%，将新内容冷启动提升2.09%。这些结果表明，共享生成式召回能够在工业规模下保留显式的目标控制，同时产生互补候选。
