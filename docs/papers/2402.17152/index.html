摘要

大规模推荐系统依赖高基数的异构特征，并且每天需要处理数百亿次用户行为。尽管使用数千个特征和海量数据进行训练， 工业界大多数深度学习推荐模型（DLRM）的效果仍无法随计算量扩展。 受 Transformer 在语言和视觉领域取得成功的启发，我们重新审视推荐系统的基本设计选择。我们将推荐问题重新表述为序列转导任务， 置于生成式建模框架（“生成式推荐器”）之下，并提出新架构 HSTU，专门面向 高基数、非平稳的流式推荐数据。 HSTU 在合成数据集和公开数据集上相较基线的 NDCG 提升最高达 65.8%，在长度为 8192 的序列上，其速度是基于 FlashAttention2 的 Transformer 的 5.3x 至 15.2x。 基于 HSTU 的生成式推荐器拥有 1.5 万亿参数，在在线 A/B 测试中将指标提升了 12.4%，并已部署于拥有数十亿用户的大型互联网平台的多个业务场景。更重要的是， 实证结果表明，生成式推荐器的模型质量随训练计算量呈幂律增长，覆盖三个数量级， 达到 GPT-3/LLaMa-2 的规模， 这减少了未来模型开发所需的碳足迹，并进一步为推荐领域首批基础模型铺平了道路。

1 引言

推荐系统是在线内容平台和电子商务的核心，每天为数十亿用户提供个性化体验，发挥着关键作用。 推荐领域最先进的方法一直基于深度学习推荐模型（DLRM） (Mudigere et al., 2022)，这一趋势已延续近十年 (Covington et al., 2016; Cheng et al., 2016; Zhou et al., 2018; Tang et al., 2020; Wang et al., 2021; Xia et al., 2023)。 DLRM 的特点是使用异构特征，例如计数器和比率等数值特征、嵌入，以及创作者 ID、用户 ID 等类别特征。由于每分钟都有新内容和新商品加入，特征空间 的基数极高，通常达到数十亿量级 (Eksombatchai et al., 2018)。为利用数以万计的此类特征，DLRM 使用各种神经网络来组合特征、变换中间表示，并形成最终输出。

尽管使用了大量人工设计的特征并在海量数据上训练， 工业界大多数 DLRM 的效果随计算量扩展的能力仍然较差 (Zhao et al., 2023)。这一局限值得关注，且其原因仍未得到解答。

受 Transformer 在语言和视觉领域取得成功的启发，我们重新审视现代推荐系统的基本设计选择。我们发现， 要在数十亿用户规模下采用其他问题表述方式，必须克服三个挑战。首先，推荐系统中的特征缺乏显式结构。虽然已有研究在小规模设置下探索序列化表述（详细讨论见 Appendix B）， 高基数 ID、交叉特征、计数器、比率等异构特征在工业级 DLRM 中发挥着关键作用 (Mudigere et al., 2022)。其次，推荐系统使用持续变化的十亿级词表。与语言领域 100K 规模的静态词表 (Brown et al., 2020) 相比，十亿级动态词表给训练带来了挑战；而由于需要以目标感知的方式考虑数以万计的候选项，推理成本也很高 (Zhou et al., 2018; Wang et al., 2020)。最后，计算成本是实现大规模序列模型的主要瓶颈。GPT-3 使用数千块 GPU，在 1-2 个月内总计训练了 300B 个 token (Brown et al., 2020)。这一规模看似惊人，但与用户行为的规模相比则并非如此。最大的互联网平台服务于数十亿日活跃用户，这些用户每天与数十亿条帖子、图片和视频互动。用户序列长度可达 10510^{5} (Chang et al., 2023)。 因此，推荐系统每天需要处理的 token 数量，比语言模型在 1-2 个月内处理的数量还要高出几个数量级。

本文将用户行为视为生成式建模中的一种新模态。我们的核心见解是：a) 在恰当的新特征空间下，工业级推荐器中的核心排序和召回任务可以表述为生成式建模问题；b) 这一范式使我们能够系统地利用特征、训练和推理中的冗余来提高效率。 借助这一新的表述方式，我们部署了计算复杂度比此前最先进模型高出三个数量级的模型，同时将核心业务指标提升了 12.4%，如 Figure 1 所示。

我们的贡献如下。我们首先提出生成式推荐器（GR），这一替代 DLRM 的新范式详见 Section 2。我们将 DLRM 中的异构特征空间序列化并统一起来；当序列长度趋于无穷时，新方法能够逼近完整的 DLRM 特征空间。这使我们能够在 GR 中将主要推荐问题——排序与召回——重新表述为纯序列转导任务。进一步而言，模型训练可以以序列化、生成式的方式进行，从而在计算量相同的条件下，使用多出几个数量级的数据进行训练。

接下来，我们解决贯穿训练与推理过程的计算成本挑战。我们提出一种新的序列转导架构——层次化序列转导单元（HSTU）。HSTU 针对大规模非平稳词表修改注意力机制，并利用推荐数据集的特征，实现 5.3x 至15.2x 的加速，比较对象为长度 8192 序列上基于 FlashAttention2 的 Transformer。此外，我们提出新算法 M-FALCON，通过微批处理充分分摊计算成本（Section 3.4）；我们能够部署复杂度高出285x的 GR 模型，同时实现 1.50x-2.99x 的加速，而所有这些都在与传统 DLRM 相同的推理预算下实现。

最后，我们在 Section 4 中通过合成数据集、公开数据集，以及在拥有数十亿日活跃用户的大型互联网平台多个业务场景中的部署，验证所提出的技术。 据我们所知，本文首次表明，在生成式设置（GR）下，HSTU 这样的纯序列转导架构能够在大规模 工业场景中显著优于 DLRM。 值得关注的是，我们不仅克服了传统 DLRM 中已知的规模扩展瓶颈， 还成功证明缩放定律 (Kaplan et al., 2020) 适用于推荐任务，表明推荐系统有望迎来自己的 ChatGPT 时刻。

2 将推荐表述为序列转导任务：从 DLRM 到 GR

2.1 统一 DLRM 中的异构特征空间

现代 DLRM 模型通常使用大量类别（“稀疏”）特征和数值（“稠密”）特征进行训练。 在 GR 中，我们将这些特征整合并编码为单一的统一时间序列，如 Figure 2 所示。

类别（“稀疏”）特征。此类特征的例子 包括用户点赞过的物品、用户关注的某一类别（例如户外）中的创作者、 用户使用的语言、用户加入的社区、请求发起的城市等。我们按如下方式将这些特征序列化。首先选择最长的时间序列作为主时间序列，通常由表示用户曾互动过的物品的特征合并而成。其余特征通常是随时间缓慢变化的时间序列，例如人口统计信息或关注的创作者。 我们仅保留每个连续片段中最早的条目，对这些时间序列进行压缩，随后将结果合并到主时间序列中。由于这些时间序列变化非常缓慢，这一方法不会显著增加整体序列长度。

数值（“稠密”）特征。此类特征包括带权重和衰减的计数器、比率等。例如，一个特征可以表示用户过去对某一主题物品的点击率（CTR）。与类别特征相比，这些特征的变化频繁得多，甚至每次（用户，物品）交互都会变化。因此，从计算和存储角度看，将这些特征完全序列化是不可行的。不过， 一个重要观察是， 我们进行这些聚合所依据的类别特征（例如物品主题、位置），已经在 GR 中被序列化并编码。 因此，只要序列转导架构具有足够强的表达能力，并且结合目标感知的表述方式 (Zhou et al., 2018)，就能够有效捕捉数值特征， 随着 GR 的整体序列长度和计算量增加，我们便可移除显式数值特征。

2.2 将排序和召回重新表述为序列转导任务

给定按时间排序的 nn 个 token x0,x1,…,xn−1x_{0},x_{1},\ldots,x_{n-1}（xi∈𝕏x_{i}\in\mathbb{X}），以及观察到这些 token 的时间 t0,t1,…,tn−1t_{0},t_{1},\ldots,t_{n-1}，序列转导任务将此输入序列映射为输出 token y0,y1,…,yn−1y_{0},y_{1},\ldots,y_{n-1}（yi∈𝕏∪{∅}y_{i}\in\mathbb{X}\cup\{\varnothing\}），其中 yi=∅y_{i}=\varnothing 表示 yiy_{i} 未定义。

我们用 Φi∈𝕏c\Phi_{i}\in\mathbb{X}_{c}（𝕏c⊆𝕏\mathbb{X}_{c}\subseteq\mathbb{X}）表示系统提供给用户的内容，例如图片或视频。 由于新内容不断产生，𝕏c\mathbb{X}_{c} 和 𝕏\mathbb{X} 是非平稳的。对于 Φi\Phi_{i}，用户可以作出某种行为 aia_{i}（例如点赞、跳过、完整观看视频并分享），其中 ai∈𝕏a_{i}\in\mathbb{X}。我们用 ncn_{c} 表示用户互动过的内容总数。

在因果自回归设置下，标准排序和召回任务便可定义为序列转导任务（Table 1）。 我们作出以下观察：

召回。在推荐系统的召回阶段，我们学习分布 p⁢(Φi+1|ui)p(\Phi_{i+1}|u_{i})，其定义域为 Φi+1∈𝕏c\Phi_{i+1}\in\mathbb{X}_{c}，其中 uiu_{i} 为用户在 token ii 处的表示。典型目标是选择 arg⁢maxΦ∈𝕏c⁡p⁢(Φ|ui)\operatorname*{arg\,max}_{\Phi\in\mathbb{X}_{c}}p(\Phi|u_{i}) 以最大化某种奖励。这与标准自回归设置有两点不同。首先，xix_{i} 的监督信号 yiy_{i} 不一定是 Φi+1\Phi_{i+1}，因为用户可能对 Φi+1\Phi_{i+1} 作出负反馈。其次，yiy_{i} 未定义的情况是：xi+1x_{i+1} 表示人口统计信息等与互动无关的类别特征。

排序。GR 中的排序任务面临独特挑战，因为工业推荐系统通常需要“目标感知”的表述方式。在这种设置下，目标 Φi+1\Phi_{i+1} 与历史特征之间的“交互” 需要尽早发生，而标准自回归设置中的“交互”发生得较晚（例如编码器输出后的 softmax），因此无法满足这一要求。我们通过将物品与行为交错排列来解决这一问题，如 Table 1 所示，这使排序任务可以表述为 p⁢(ai+1|Φ0,a0,Φ1,a1,…,Φi+1)p(a_{i+1}|\Phi_{0},a_{0},\Phi_{1},a_{1},\ldots,\Phi_{i+1})（尚未加入类别特征）。 实际中，我们使用一个小型神经网络，将 Φi+1\Phi_{i+1} 处的输出 转换为多任务预测。关键在于，这使我们能够在一次前向过程中，对所有 ncn_{c} 次互动应用目标感知的交叉注意力。

2.3 生成式训练

工业推荐器通常采用流式训练设置，每个样本 在可用时依次被处理。 在这种设置下，Transformer (Vaswani et al., 2017) 等基于自注意力的序列转导架构，其总计算需求随下式增长：∑ini⁢(ni2⁢d+ni⁢df⁢f⁢d)\sum_{i}n_{i}(n_{i}^{2}d+n_{i}d_{ff}d)，其中 nin_{i} 为用户 ii 的 token 数量，dd 为嵌入维度。 括号中的第一项 来自自注意力，假设其扩展因子为 O⁢(n2)O(n^{2})，因为大多数次二次复杂度算法都需要在效果上作出权衡，而且实际运行时间不如二次复杂度算法 (Dao et al., 2022)。第二项来自逐点 MLP 层，其隐藏层大小为 O⁢(df⁢f)=O⁢(d)O(d_{ff})=O(d)。令 N=maxi⁡niN=\max_{i}n_{i}，则整体时间复杂度简化为 O⁢(N3⁢d+N2⁢d2)O(N^{3}d+N^{2}d^{2})，这一成本对推荐场景而言难以承受。

为解决长序列上的序列转导模型难以扩展训练的问题，我们将传统曝光级训练改为生成式训练，使计算复杂度降低 O⁢(N)O(N) 倍，如图 2 上部所示。这样，编码器的成本便能在多个目标之间分摊。具体而言，当对第 ii 个用户采用 su⁢(ni)s_{u}(n_{i}) 的采样率时，总训练成本随下式增长： ∑isu⁢(ni)⁢ni⁢(ni2⁢d+ni⁢d2)\sum_{i}s_{u}(n_{i})n_{i}(n_{i}^{2}d+n_{i}d^{2})；其复杂度可降至 O⁢(N2⁢d+N⁢d2)O(N^{2}d+Nd^{2})，方法是将 su⁢(ni)s_{u}(n_{i}) 设为 1/ni1/n_{i}。在工业级系统中，实现这种采样的一种方式是在用户请求或会话结束时产生训练样本，从而得到 su^⁢(ni)∝1/ni\hat{s_{u}}(n_{i})\propto 1/n_{i}。

HSTU 的编码器设计使得 DLRM 中的异构 模块能够由单一的模块化结构替代。我们观察到，DLRM 实际上包含三个主要阶段： 特征提取、特征交互和 表示变换。特征提取获取类别特征的池化嵌入表示。其最先进的形式可以归纳为成对注意力和目标感知池化 (Zhou et al., 2018)，这些操作能够由 HSTU 层实现。

特征交互是 DLRM 中最关键的部分。常用方法 包括因子分解机及其神经网络变体  (Rendle, 2010; Guo et al., 2017; Xiao et al., 2017)、高阶特征交互 (Wang et al., 2021) 等。 HSTU 通过 Norm⁢(A⁢(X)⁢V⁢(X))⊙U⁢(X)\text{Norm}\left(A(X)V(X)\right)\odot U(X)，使经过注意力池化的特征直接与其他特征“交互”，从而替代显式特征交互模块。这一设计源于学习得到的 MLP 难以逼近点积这一问题 (Rendle et al., 2020; Zhai et al., 2023a)。由于 U⁢(X)U(X) 上应用了 SiLU，Norm⁢(A⁢(X)⁢V⁢(X))⊙U⁢(X)\text{Norm}\left(A(X)V(X)\right)\odot U(X) 也可以解释为 SwiGLU 的一种变体 (Shazeer, 2020)。

表示变换通常通过混合专家（MoE）及路由完成，以处理多样化的异构人群。一个关键思路 是为不同用户专门设置子网络，以进行条件计算 (Ma et al., 2018; Tang et al., 2020)。HSTU 中的逐元素点积实际上能够实现 MoE 中的门控操作，仅相差一个归一化因子。

3.1 逐点聚合注意力

HSTU 采用新的逐点聚合（归一化）注意力机制；相比之下，softmax 注意力在整个序列上计算归一化因子。 这一设计由两个因素驱动。首先， 与目标相关的历史数据点数量，是表征用户偏好强度的重要特征，而 softmax 归一化后难以捕捉这一信息。这一点很关键，因为我们既要预测互动强度（例如在某一物品上花费的时间），也要预测物品的相对顺序，例如预测一种排序， 以最大化 AUC。其次，尽管 softmax 激活在设计上对噪声具有稳健性，但它不太适合流式设置中的非平稳词表。

所提出的逐点聚合注意力机制见 Equation 2。 为稳定训练，需要在逐点池化之后进行层归一化。 理解这一设计的一种方式是使用遵循狄利克雷过程的合成数据，该过程在非平稳词表上生成流式数据（详见附录 C）。在这一设置下，softmax 注意力与逐点注意力之间的差距可达 44.7%， 如 Table 2 所示。

3.2 利用稀疏性并通过算法增强稀疏性

在推荐系统中，用户历史序列长度通常呈偏斜分布，导致输入序列具有稀疏性，在极长序列设置下尤其如此。可以利用这种稀疏性显著提高编码器效率。 为此，我们开发了高效的 GPU 注意力内核，以类似于 (Rabe & Staats, 2021; Dao et al., 2022) 的方式融合连续的 GEMM， 但采用完全不规则长度的注意力计算。这实际上将 注意力计算转换为一组大小不一的分组 GEMM（Appendix G）。 因此，HSTU 中的自注意力受到内存带宽限制，其内存访问量 按 Θ⁢(∑ini2⁢dq⁢k2⁢R−1)\Theta(\sum_{i}n_{i}^{2}d_{qk}^{2}R^{-1}) 扩展，其中 nin_{i} 是 样本 ii 的序列长度，dq⁢kd_{qk} 为注意力维度，RR 为寄存器大小。仅这一方法 就带来了 2-5x 的吞吐量提升，详见 Section 4.2。

3.3 最小化激活内存使用量

在推荐系统中，使用较大的批大小对于 训练吞吐量 (Mudigere et al., 2022) 和 模型质量 (Yang et al., 2020; Chen et al., 2020; Zhai et al., 2023a) 都十分关键。 因此，激活内存使用量成为规模扩展的主要瓶颈； 相比之下，大语言模型通常以较小批大小训练，内存占用主要来自模型参数。

与 Transformer 相比，HSTU 采用简化且充分融合的设计，显著减少激活内存使用量。首先，HSTU 将注意力之外的线性层数量从六个减少到两个， 这与近期通过逐元素门控减少 MLP 计算的工作一致 (Hua et al., 2022; Gu et al., 2022)。 其次，HSTU 将多项计算大幅融合为单个算子，包括 ϕ1⁢(f1⁢(⋅))\phi_{1}(f_{1}(\cdot))（见 Equation 1），以及层归一化、可选的 dropout 和输出 MLP， 后者见 Equation 3。 这种简化设计 将激活内存使用量降至 2⁢d+2⁢d+4⁢h⁢dq⁢k+4⁢h⁢dv+2⁢h⁢dv=14⁢d2d+2d+4hd_{qk}+4hd_{v}+2hd_{v}=14d 每层，使用 bfloat16 精度。

作为对比，Transformer 在注意力之后使用前馈层和 dropout（中间状态为 3⁢h⁢dv3hd_{v}），随后是由层归一化、线性层、激活、线性层和 dropout 构成的逐点前馈模块，中间状态为 2⁢d+4⁢df⁢f+2⁢d+1⁢d=4⁢d+4⁢df⁢f2d+4d_{ff}+2d+1d=4d+4d_{ff}。这里采用标准假设：h⁢dv≥dhd_{v}\geq d 且 df⁢f=4⁢dd_{ff}=4d (Vaswani et al., 2017; Brown et al., 2020)。因此，计入输入与输入层归一化（4⁢d4d）及 qkv 投影后，总激活状态为 33⁢d33d。因此，HSTU 的设计允许模型层数扩展到 >2>2x 的深度。

此外，用于表示词表的大规模原子 ID 也需要大量内存。对于 10b 词表、512d 嵌入和 Adam 优化器，仅以 fp32 存储嵌入及优化器状态就需要 60TB 内存。 为缓解内存压力， 我们采用逐行 AdamW 优化器 (Gupta et al., 2014; Khudia et al., 2021)，并将优化器状态放在 DRAM 中， 将每个浮点数的 HBM 使用量从 12 字节降至 2 字节。

3.4 通过成本分摊扩展推理

我们要解决的最后一个挑战，是推荐系统在线服务时需要处理的大量候选项。 我们重点讨论排序，因为在召回中，编码器成本可以被完全分摊；对于 MIPS，已有利用量化、哈希或分区的高效算法 (Jegou et al., 2011; Shrivastava & Li, 2014; Li et al., 2002; Zhai et al., 2011)，对于非 MIPS 情况，也可以使用束搜索或层次化召回 (Zhuo et al., 2020; Zhai et al., 2023a)。

排序阶段的候选项数量可达数万 (Covington et al., 2016; Wang et al., 2020)。 我们提出 M-FALCON 算法（Microbatched-Fast Attention Leveraging Cacheable OperatioNs，利用可缓存操作的微批次快速注意力）， 用于对 mm 个候选项执行推理，输入序列长度为 nn。

在一次前向过程中，M-FALCON 并行处理 bmb_{m} 个候选项，方法是修改注意力掩码与 rabp,t\text{rab}^{p,t} 偏置，使 bmb_{m} 个候选项执行完全相同的注意力操作。这将交叉注意力的成本从 O⁢(bm⁢n2⁢d)O(b_{m}n^{2}d) 降至 O⁢((n+bm)2⁢d)=O⁢(n2⁢d)O((n+b_{m})^{2}d)=O(n^{2}d)，条件是 bmb_{m} 相对于 nn 可视为一个小常数。我们还可以将全部 mm 个候选项划分为 ⌈m/bm⌉\lceil m/b_{m}\rceil 个大小为 bmb_{m} 的微批次，以利用编码器级 KV 缓存 (Pope et al., 2022)：既可以跨前向过程复用以降低成本，也可以跨请求复用以最小化尾部延迟（更详细的讨论见 Appendix H）。

总体而言，M-FALCON 使模型复杂度能够随传统 DLRM 排序阶段的候选项数量 线性扩展；我们成功应用了复杂度高出285x 的目标感知交叉注意力模型，并实现 1.5x-3x 的吞吐量，同时保持典型排序配置下的推理预算不变， 该配置详见 Section 4.3。

4.3.1 推荐系统的缩放定律

众所周知，在大规模工业设置下，DLRM 的效果会在一定计算量和参数规模下趋于饱和 (Zhao et al., 2023)。 我们比较 GR 与 DLRM 的可扩展性，以更好地理解这一现象。

由于特征交互层对 DLRM 的性能至关重要 (Mudigere et al., 2022)，我们尝试了 Transformer (Vaswani et al., 2017)、DHEN (Zhang et al., 2022)，以及生产环境中使用的 DCN (Wang et al., 2021) 变体（加入残差连接 (He et al., 2015)），以扩大排序设置中的 DLRM 基线规模。对于召回基线，由于其采用残差结构，我们扩大了隐藏层大小、嵌入维度和层数。对于基于 HSTU 的生成式推荐器（GR），我们通过调整 HSTU 的超参数扩大模型规模，包括残差层数、序列长度、嵌入维度、注意力头数等。对于召回，我们还调整了负例数量。

结果见 Figure 7。 在低计算量设置下，DLRM 可能因人工特征而优于 GR，这印证了特征工程在传统 DLRM 中的重要性。 然而，GR 在 FLOPs 方面表现出显著更好的可扩展性， 而 DLRM 的性能趋于平台期，与既有研究的发现一致。我们还观察到，GR 在嵌入参数和非嵌入参数方面均具有更好的可扩展性，能够扩展到 1.5 trillion 参数模型，而 DLRM 的性能在约 200 billion 参数时便趋于饱和。

最后，在采用合适超参数时，我们的所有主要指标，包括召回的 Hit Rate@100 和 Hit Rate@500，以及排序的 NE，都在实验中随所用计算量呈幂律变化。我们在三个数量级的范围内观察到了这一现象，直至能够测试的最大模型（序列长度 8,192、嵌入维度 1,024、24 层 HSTU）。此时，我们使用的总计算量（由于采用标准流式训练设置，按 365 天归一化）已接近 GPT-3 (Brown et al., 2020) 和 LLaMa-2 (Touvron et al., 2023b) 的总训练计算量，如 Figure 1 所示。在合理范围内，相比投入的总训练计算量，具体模型超参数的作用较小。与语言建模 (Kaplan et al., 2020) 相比，序列长度在 GR 中起着明显更重要的作用，因此应当将序列长度与其他参数 同步扩大。这或许是所提方法最重要的优势，因为我们首次表明，LLM 的缩放定律也可能适用于大规模推荐系统。

5 相关工作

既有序列推荐器工作将用户交互简化为物品上的单一同质序列 (Hidasi et al., 2016; Kang & McAuley, 2018)。 序列方法在工业规模中的应用主要是成对注意力 (Zhou et al., 2018)，或作为 DLRM 组成部分的序列编码器 (Chen et al., 2019; Xia et al., 2023)。已有研究探索以多阶段注意力替代自注意力， 以提高效率 (Chang et al., 2023)。将 ID 表示为 token 序列的生成式方法已在召回任务中得到探索 (Zhuo et al., 2020)。我们在 Section B.1 中更全面地讨论了既有工作。

高效注意力一直是重要研究方向， 原因在于自注意力具有 O⁢(n2)O(n^{2}) 的复杂度增长，代表性工作包括分解式注意力 (Child et al., 2019)、低秩近似 (Katharopoulos et al., 2020)， 等等。近期，已有研究探索了序列转导设置的其他表述方式 (Gu et al., 2022; Hua et al., 2022)。其中，HSTU 的逐元素门控设计受到 FLASH (Hua et al., 2022) 的启发。近期感知硬件的表述方式被证明能够显著降低内存用量 (Rabe & Staats, 2021; Korthikanti et al., 2022; Zhai et al., 2023b)，并明显改善实际运行时间  (Dao et al., 2022)。 长度外推使在较短序列上训练的模型能够泛化，但多数工作侧重于微调或改进偏置机制  (Press et al., 2022)。相比之下，我们受到在深度维度引入随机性的工作 (Huang et al., 2016) 启发，在长度维度引入随机性。

对大语言模型（LLM）的关注催生了一系列工作，将各种推荐任务 建模为基于预训练 LLM 的上下文学习 (Sileo et al., 2022)、指令微调 (Bao et al., 2023) 或迁移学习 (Li et al., 2023)。 LLM 中蕴含的世界知识能够迁移到下游任务 (Cui et al., 2022)，改善零样本或少样本情况下的推荐。用户行为序列的文本表示也在中等规模数据集上展现出良好的规模扩展特性 (Shin et al., 2023)。 大多数将 LLM 用于推荐的研究 都集中在 数据稀缺的场景；在大规模设置下，这些方法尚未在 MovieLens 上超越协同过滤  (Hou et al., 2024)。

6 结论

我们提出了生成式推荐器（GR）这一新范式，将排序和召回表述为序列转导任务，从而能够以生成式方式进行训练。 这一范式得益于新颖的 HSTU 编码器设计，其速度可达到最先进 Transformer 的 5.3x-15.2x， 这一比较采用长度为 8192 的序列，同时也得益于 M-FALCON 等新的训练和推理算法。 借助 GR，我们部署了 复杂度高出285x、但推理计算量更少的模型。GR 和 HSTU 在生产环境中带来了 12.4% 的指标提升， 并展现出优于传统 DLRM 的规模扩展表现。 我们的结果印证了，用户行为是生成式建模中尚未得到充分探索的一种模态， 也呼应了本文标题：“行动胜于语言”。

本文对特征进行了大幅简化， 通过支持跨领域使用统一特征空间， 为推荐、搜索和广告领域的首批基础模型铺平了道路。GR 的全序列化设置也使推荐能够被表述为端到端的生成式任务。这两点都使推荐系统能够更全面地帮助用户。

影响声明

我们认为，本文工作具有广泛的积极意义。减少推荐、搜索和广告系统对大量异构特征的依赖，能够在改善用户体验的同时，使这些系统更加注重隐私保护。 通过全序列化表述，使推荐系统能够将用户的长期结果归因于短期决策，可以减少互联网上不符合用户长期目标的内容（包括标题党和虚假新闻），并使平台的激励机制更好地与用户价值保持一致。最后，基础模型和缩放定律的应用有助于减少推荐、搜索及相关场景所需的模型研发产生的碳足迹。

Appendix B 生成式推荐器：背景与问题形式化

许多读者可能更熟悉传统的深度学习推荐模型（DLRM） (Mudigere et al., 2022)，因为这类模型自 YouTube DNN 时代 (Covington et al., 2016) 起便广受关注，并已广泛用于各大在线内容平台和电商平台 (Cheng et al., 2016; Zhou et al., 2018; Wang et al., 2021; Chang et al., 2023; Xia et al., 2023; Zhai et al., 2023a)。DLRM 在异构特征空间上使用各种神经网络，包括特征交互模块 (Guo et al., 2017; Xiao et al., 2017; Wang et al., 2021)、序列池化或目标感知的成对注意力模块 (Hidasi et al., 2016; Zhou et al., 2018; Chang et al., 2023)，以及先进的多专家多任务模块 (Ma et al., 2018; Tang et al., 2020)。因此，我们在 Section 2 和 Section 3 中通过与传统 DLRM 明确对比，概述了生成式推荐器（GR）。本节从经典序列推荐文献出发，为读者提供另一种视角。

B.1 背景：学术界与工业界的序列推荐

B.1.1 学术研究（传统序列推荐设置）

循环神经网络（RNN）最早由 GRU4Rec (Hidasi et al., 2016) 应用于推荐场景。Hidasi et al. (2016) 采用门控循环单元（GRU），并将其应用于 RecSys Challenge 2015 22 2 http://2015.recsyschallenge.com/ 和 VIDEO（一个私有数据集）这两个数据集。在这两种情况下，输入序列中仅保留正向事件（用户点击的电商商品，或观看时长至少达到一定阈值的视频）。我们进一步观察到，在由召回和排序阶段组成的经典工业级两阶段推荐系统 (Covington et al., 2016) 中，Hidasi et al. (2016) 所解决的任务主要对应召回任务。

Transformer、序列转导架构及其变体。此后数年序列转导架构的进展，尤其是 Transformer (Vaswani et al., 2017) 的发展，也推动了推荐系统的类似进步。SASRec (Kang & McAuley, 2018) 首次在自回归设置中应用 Transformer。它将评论或评分的存在视为正向反馈，从而像 GRU4Rec 一样，将 Amazon Reviews 33 3 https://jmcauley.ucsd.edu/data/amazon/ 和 MovieLens 44 4 https://grouplens.org/datasets/movielens/1m/, https://grouplens.org/datasets/movielens/20m/ 等经典数据集转换为正向物品序列。它使用二元交叉熵损失，将下一个“正向”物品定义为正样本目标（注意，这实际上只是存在评论或评分），并从物品全集 𝕏=𝕏c\mathbb{X}=\mathbb{X}_{c} 中随机采样负样本目标。

后续大多数研究都基于与上述 GRU4Rec (Hidasi et al., 2016) 和 SASRec (Kang & McAuley, 2018) 类似的设置，例如 BERT4Rec (Sun et al., 2019) 应用了 BERT (Devlin et al., 2019) 的双向编码器设置，以及引入显式预训练阶段的 S3Rec (Zhou et al., 2020) 等。

B.1.2 作为深度学习推荐模型（DLRM）组成部分的工业应用。

包括序列编码器和成对注意力模块在内的序列方法，能够作为 DLRM 的组成部分增强用户表征，因此已广泛用于工业场景。DLRM 通常采用相对较短的序列，例如 BST (Chen et al., 2019) 的 20、DIN (Zhou et al., 2018) 的 1,000，以及 TransAct (Xia et al., 2023) 的 100。我们注意到，这些长度比本文采用的 8,192（Section 4.3）小 1-3 个数量级。

尽管采用较短的序列，大多数 DLRM 仍能有效捕捉用户的长期偏好。这可以归因于两个关键因素。首先，现代 DLRM 通常使用预先计算的用户画像/嵌入 (Xia et al., 2023) 或外部向量存储 (Chang et al., 2023)，两者都能有效扩展回溯窗口。其次，模型通常采用大量上下文、用户侧和物品侧特征 (Zhou et al., 2018; Chen et al., 2019; Chang et al., 2023; Xia et al., 2023)，并使用 FM (Xiao et al., 2017; Guo et al., 2017)、DCN (Wang et al., 2021)、MoE 等各种异构网络来变换表征并融合输出。

与 Section B.1.1 中讨论的序列设置不同，主流工业研究都在（用户/请求，候选物品）对上定义损失。在排序设置中，通常使用多任务二元交叉熵损失。在召回设置中，双塔设置 (Covington et al., 2016) 仍是主流方法。近期研究探索了将下一个推荐物品表示为（子）token 序列上的概率分布，例如 OTM (Zhuo et al., 2020) 和 DR (Gao et al., 2021)（注意，在其他近期工作中，同一设置有时被称为“生成式召回”）。这类方法通常使用束搜索从子 token 中解码出物品。随着 GPU、定制 ASIC 和 TPU 等现代加速器的普及，研究者也提出并部署了先进的可学习相似度函数，例如 mixture-of-logits (Zhai et al., 2023a)，作为双塔设置和束搜索的替代方案。

从问题形式化的角度来看，我们将上述所有工作都归入 DLRM (Mudigere et al., 2022)，因为其模型架构、所用特征和损失函数都与 Section B.1.1 中讨论的学术序列推荐研究存在显著差异。还应指出，在本文工作之前，工业界尚未成功应用完全序列化的排序设置，尤其未曾达到十亿级日活跃用户（DAU）的规模。

B.2 问题形式化：将排序和召回作为生成式推荐器（GR）中的序列转导任务

接下来，我们讨论传统序列推荐设置和 DLRM 设置中的三个局限， 以及生成式推荐器（GR）如何从问题形式化的角度解决这些局限。

忽略用户交互物品之外的特征。以往的序列形式化仅考虑用户显式交互过的内容（物品） (Hidasi et al., 2016; Kang & McAuley, 2018; Sun et al., 2019; Zhou et al., 2020)， 而 GR 出现之前的工业级推荐系统则使用大量特征进行训练，以增强用户和内容的表征 (Covington et al., 2016; Cheng et al., 2016; Zhou et al., 2018; Chen et al., 2019; Chang et al., 2023; Xia et al., 2023; Zhai et al., 2023a)。GR 通过以下方式解决这一局限：a）压缩其他类别特征，并将其合并到主时间序列中；b）如 Section 2.1 和 Figure 2 所述，采用目标感知的形式化，通过交叉注意力交互捕捉数值特征。我们验证了这一点：忽略这些特征的传统“仅交互”形式化会显著降低模型质量；实验结果见 Table 7 和 Table 6 中标记为“GR (interactions only)”的行。仅使用交互历史会导致召回的 hit rate@100 下降 1.3%，排序的 NE 下降 2.6%（如 Sections 4.1.2 and 4.3.1 所述，NE 变化 0.1% 就已具有显著意义）。

在目标无关的设置中计算用户表征。第二个问题是，大多数传统序列推荐器，包括 GRU4Rec (Hidasi et al., 2016)、SASRec (Kang & McAuley, 2018)、BERT4Rec (Sun et al., 2019)、S3Rec (Zhou et al., 2020) 等，都采用目标无关的形式化：对于目标物品 Φi\Phi_{i}，使用 Φ0,Φ1,…,Φi−1\Phi_{0},\Phi_{1},\ldots,\Phi_{i-1} 作为编码器输入来计算用户表征，再用该表征 进行预测。相比之下，工业场景中大多数主流 DLRM 方法都以目标感知的方式构建所用的序列模块，能够将“目标”（排序候选）信息融入用户表征。这些方法包括 DIN (Zhou et al., 2018)（阿里巴巴）、BST (Chen et al., 2019)（阿里巴巴）、TWIN (Chang et al., 2023)（快手）和 TransAct (Xia et al., 2023)（Pinterest）。

生成式推荐器（GR）通过交错排列内容序列和行为序列（Section 2.2），结合了两类方法的优势，使目标感知注意力能够应用于因果自回归设置。我们在 Table 10 55 5 由于日志数据量庞大，大多数大规模工业推荐器都需要在流式/单遍设置下训练。 中对以往工作和本文工作进行了分类与对比。

判别式形式化将以往序列推荐工作的适用范围限制在逐点设置。最后，传统序列推荐器在设计上采用判别式建模。现有序列推荐文献，包括 GRU4Rec 和 SASRec 等开创性工作， 建模的是 p⁢(Φi|Φ0,a0,…,Φi−1,ai−1)p(\Phi_{i}|\Phi_{0},a_{0},\ldots,\Phi_{i-1},a_{i-1})，即给定用户当前状态时下一个推荐物品的条件分布。另一方面，我们观察到，标准推荐系统包含两个概率过程，即推荐系统向用户推荐内容 Φi\Phi_{i}（例如某张照片或某段视频）的过程，以及用户对推荐内容 Φi\Phi_{i} 通过某种行为 aia_{i} 作出反应的过程（行为可以是点赞、视频完播、跳过等的组合）。

如 Section 2.2 所述，生成式方法需要对推荐内容与用户行为序列的联合分布，即 p⁢(Φ0,a0,Φ1,a1,…,Φnc−1,anc−1)p(\Phi_{0},a_{0},\Phi_{1},a_{1},\ldots,\Phi_{n_{c}-1},a_{n_{c}-1}) 进行建模。我们提出的生成式推荐器能够建模此类分布，如 Table 11（Figure 8）所示。注意，下一个行为 token（aia_{i}）预测任务正是 Table 1 中讨论的 GR 排序设置，而下一个内容（Φi\Phi_{i}）预测任务类似于适配至交错序列的召回设置，其目标经过调整，以学习输入数据分布。

这一形式化不仅能够恰当地建模数据分布，还允许通过束搜索等方法直接采样出向用户推荐的物品序列。我们假设，与传统列表式设置（例如 DPP (Gillenwater et al., 2014) 和 RL (Zhao et al., 2018)）相比，这将带来更优的方法；此类系统的完整形式化与评估（在 Section 6 中有简要讨论）将留待未来研究。

Appendix C 评估：合成数据

如 Section 3.1 先前所述，标准 softmax 注意力的归一化因子使其难以捕捉用户偏好的强度，而这一点对用户表征学习十分重要。这在推荐场景中很关键，因为系统除了预测物品的相对顺序，还可能需要预测参与行为的强度（例如未来围绕特定主题发生的正向行为次数）。

为理解这一现象，我们按照狄利克雷过程构造合成数据，在动态词表上生成流式数据。狄利克雷过程可以捕捉用户参与历史中“强者愈强”的现象。合成实验设置如下：

  • •

    将 20,000 个物品 id 中的每一个随机分配给 100 个类别中的恰好一个。

  • •

    生成 1,000,000 条记录，每条长度为 128，前 90% 用于训练，最后 10% 用于测试。为模拟流式训练设置，初始仅开放前 40% 的物品 id，其余 id 按等间隔逐步开放；也就是说，到第 500,000 条记录时，可采样的最大 id 为 (40%+60%∗0.5)∗20,000=14,000(40\%+60\%*0.5)*20,000=14,000。

  • •

    对每条记录，从 100 个类别中随机选择至多 5 个，并在这 5 个类别上随机采样先验 HcH_{c}。随后按如下狄利克雷过程，依次为各位置从可能的类别中采样：

    • –

      当 n>1n>1 时：

      • *

        以概率 α/(α+n−1)\alpha/(\alpha+n-1)，抽取类别 cc，其分布为 HcH_{c}。

      • *

        以概率 nc/(α+n−1)n_{c}/(\alpha+n-1) 抽取类别 cc，其中 ncn_{c} 是此前属于类别 cc 的物品数量。

      • *

        在满足流式约束的条件下，随机采样一个被分配到类别 cc 的物品。

    其中，α\alpha 从 (1.0,500.0)(1.0,500.0) 中均匀随机采样。

结果见表 2。由于该数据集没有时间戳，我们始终在 HSTU 中移除 rabp,t\text{rab}^{p,t}。相对于标准 Transformer，HSTU 将 Hit Rate@10 提高了超过 100%。另外，将 HSTU 的逐点注意力机制替换为 softmax（“HSTU w/ Softmax”）也会使命中率显著下降，这验证了类似逐点注意力的聚合机制的重要性。

Appendix E 评估：传统 DLRM 基线

Section 4 中使用的 DLRM 基线配置，是数百名研究人员和工程师历经多年持续迭代的成果，非常接近一个拥有数十亿日活跃用户的大型互联网平台在部署 HSTU/GR 之前的生产配置。下面从整体上介绍所用模型。

排序设置。如 (Mudigere et al., 2022) 所述，排序基线模型采用约一千个稠密特征和五十个稀疏特征。我们结合了混合专家 (Ma et al., 2018)、Deep & Cross Network 的变体 (Wang et al., 2021)、包括目标感知成对注意力在内的各种序列推荐模块（工业场景中的一种常用变体见 (Zhou et al., 2018)），以及特殊交互层上的残差连接 (He et al., 2015; Zhang et al., 2022) 等多种建模技术。对于缩放定律一节（Section 4.3.1）中的低 FLOPs 区间，我们简化了一些计算成本较高的模块，和/或将其替换为 DCN 等其他先进变体，以达到目标 FLOPs。

出于保密考虑，我们无法披露精确配置，但据我们所知，在充分吸收近期研究成果后，我们的基线属于已知最好的 DLRM 方法之一。为验证这一点并帮助读者理解，我们报告了一种采用相同特征、但仅使用 DIN (Zhou et al., 2018)、DCN (Wang et al., 2021) 和 MMoE (Ma et al., 2018) 等主要已发表成果的典型配置（“DLRM (DIN+DCN)”），结果见 Table 7，其组合架构见 Figure 9。该配置明显逊于我们的生产 DLRM 配置：在主要 E-Task 和主要 C-Task 上，NE 分别差 0.71% 和 0.57%（NE 差异达到 0.1% 就已具有显著意义）。

召回设置。召回基线模型采用标准双塔神经召回设置 (Covington et al., 2016)，混合使用批内和批外采样。输入特征集同时包含高基数稀疏特征（例如物品 id、用户 id）和低基数稀疏特征（例如语言、主题、兴趣实体）。带有残差连接 (He et al., 2015) 的多层前馈网络将输入特征压缩为用户和物品嵌入。

特征与序列长度。两个 DLRM 基线所用的特征，包括各种序列编码器/成对注意力模块利用的主要用户交互历史，都是所有 GR 候选模型所用特征的严格超集。这一点适用于本文的全部研究，包括缩放研究（Section 4.3.1）。

Appendix G 稀疏分组 GEMM 与融合相对注意力偏置

这里补充介绍高效 HSTU 注意力内核的相关信息， 该内核已在 Section 3.2 中介绍。 我们的方法基于 Memory-efficient Attention (Rabe & Staats, 2021) 和 FlashAttention (Dao et al., 2022)，是一种内存高效的自注意力机制：它将输入分块，避免为反向传播显式存储巨大的 h×N×Nh\times N\times N 中间注意力张量。通过利用输入序列的稀疏性， 我们可以将注意力计算重新表示为一组连续执行的 GEMM， 这些 GEMM 具有不同形状。我们实现了高效的 GPU 内核来加速这一计算。 由于涉及内存访问，相对注意力偏置的构造也是一个瓶颈。 为解决这一问题，我们将相对偏置构造和分组 GEMM 融合到单个 GPU 内核中，并在反向传播时利用 GPU 的高速共享内存累积梯度。尽管我们的算法需要在反向传播时重新计算注意力和相对偏置，但与 Transformer 使用的标准方法相比，它的速度显著更快，内存占用也更少。

Appendix H 利用可缓存运算的微批次快速注意力（M-FALCON）

本节详细介绍 Section 3.4 中讨论的 M-FALCON 算法。M-FALCON 的伪代码见 Algorithm 1。M-FALCON 引入了三个关键思想。

批量推理可用于因果自回归设置。如 Section 2.2 所述，GR 中的排序任务采用目标感知的形式化。通常认为，在目标感知设置中，每次只能对一个物品进行推理，其成本为 O⁢(m⁢n2⁢d)O(mn^{2}d)，其中候选数为 mm，序列长度为 nn。这里我们表明，这并非最优方案；即使使用原始 Transformer，也可以修改自注意力所用的注意力掩码，将这些运算批量执行（“批量推理”），从而将成本降至 O⁢((n+m)2⁢d)=O⁢(n2⁢d)O((n+m)^{2}d)=O(n^{2}d)。

示意见 Figure 11。这里，Figure 11 的 (a) 和 (b) 都包含用于因果自回归设置的注意力掩码矩阵。关键区别在于，Figure 11 (a) 使用大小为 2⁢nc2n_{c} 的标准下三角矩阵进行因果训练，而 Figure 11 (b) 则修改大小为 2⁢nc+bm2n_{c}+b_{m} 的下三角矩阵，将索引为 (i,j)(i,j) 且满足 i,j≥2⁢nc,i≠ji,j\geq 2n_{c},i\neq j 的元素设为 False 或 −∞-\infty，以防止目标位置 Φ0′,…,Φbm−1′\Phi^{\prime}_{0},\ldots,\Phi^{\prime}_{b_{m}-1} 相互关注。容易看出，通过这种方式，自注意力块针对 Φi′\Phi^{\prime}_{i} 的输出 ai′a^{\prime}_{i} 仅依赖于 Φ0,a0,…,Φnc−1,anc−1\Phi_{0},a_{0},\ldots,\Phi_{n_{c}-1},a_{n_{c}-1}，而不依赖于 Φj′\Phi^{\prime}_{j}（i≠ji\neq j）。换言之，使用修改后的注意力掩码，对 (2⁢nc+bm)(2n_{c}+b_{m}) 个 token 执行一次前向传播，即可得到最后 bmb_{m} 个 token 的结果，这与分别进行 bmb_{m} 次、每次针对 (2⁢nc+1)(2n_{c}+1) 个 token 的前向传播所得结果相同；在后一种方式中，将 Φi′\Phi^{\prime}_{i} 放在第 2⁢nc2n_{c} 个位置（从 0 开始计数），并在第 ii 次前向传播中使用标准因果注意力掩码。

微批次使批量推理扩展到大规模候选集。排序阶段可能需要处理大量排序候选，数量可达数万 (Wang et al., 2020)。我们可以将总计 mm 个候选分成 ⌈m/bm⌉\lceil m/b_{m}\rceil 个微批次，每个微批次大小为 bmb_{m}，满足 O⁢(bm)=O⁢(n)O(b_{m})=O(n)。这样，在大多数实际推荐设置中，即使候选数达到数万，也能保持前文讨论的 O⁢((n+m)2⁢d)=O⁢(n2⁢d)O((n+m)^{2}d)=O(n^{2}d) 运行时间。

编码器级缓存可实现请求内及跨请求的计算共享。最后，KV 缓存 (Pope et al., 2022) 既可用于同一请求内部，也可跨请求使用。例如，对于本文提出的 HSTU 模型（Section 3），K⁢(X)K(X) 和 V⁢(X)V(X) 可以在请求内和/或跨请求的微批次之间完整缓存。对于使用缓存的前向传播，只需计算 U⁢(X)U(X)、Q⁢(X)Q(X)、K⁢(X)K(X) 和 V⁢(X)V(X) 在最后 bmb_{m} 个 token 上的值，同时复用已缓存的 K⁢(X)K(X) 和 V⁢(X)V(X)，它们对应包含 nn 个 token 的序列化用户历史。同样，f2⁢(Norm⁢(A⁢(X)⁢V⁢(X))⊙U⁢(X))f_{2}(\text{Norm}{(A(X)V(X))}\odot U(X)) 也只需针对 bmb_{m} 个候选重新计算。这将带缓存的前向传播计算复杂度降低至 O⁢(bm⁢d2+bm⁢n⁢d)O(b_{m}d^{2}+b_{m}nd)，相较于 O⁢((n+bm)⁢d2+(n+bm)2⁢d)O((n+b_{m})d^{2}+(n+b_{m})^{2}d)，即使在 bm=nb_{m}=n 时也有 2-4 倍的显著改善。
