UserArena：面向长程购物智能体的交互式用户模拟基准

UserArena: Benchmarking Interactive User Simulation for Long-Horizon Shopping Agents ↗

全文机构行（模型提取） · 论文更新于 2026-10-22（UTC）

适合做 LLM 用户模拟、离线策略评估或 A/B 预演的推荐/搜索团队；亮点是真实长程轨迹、Replay/Rollout 分离、五级指标和与生产 A/B 的对齐结果。

研究问题

Agentic 推荐需要在长程购物交互中训练和评估策略，但现有资源缺少同时对齐用户画像、视觉观察、商品上下文与动作的细粒度真实轨迹，也缺少用生产 A/B 结果检验模拟器结论的协议。

核心方法

论文构建 UserArena：真实电商交互环境（13 类动作）加 64,729 条 session 轨迹，并将同一用户 59,378 个 session 串成跨 session 长程轨迹；评测分 L0–L4 五级，区分 Replay 与 Rollout。方法 OPTD 将完整轨迹抽取的轨迹级意图作为冻结教师的特权上下文，在学生的在策略 rollout 上提供稠密教师目标，并用 per-token KL 信任域约束意图影响，另加记录动作的 grounding loss。

实验结果

  • UserArena 含 64,729 条 session 轨迹、11,010 名用户、566,102 个商品和 13 类动作，来自真实电商交互。
  • 单 session 下，OPTD 在全部 8 个 L1–L4 指标上排名第一，覆盖局部、序列、个性化群体和结果保真度。
  • 跨 session 下，OPTD 在 8 个 L1–L4 指标中 5 个第一、2 个第二，整体领先。
  • 生产 A/B 对齐中，OPTD 最接近线上策略效应，效果比 0.713。

工程 insight 分析推断

  • 不要只用 next-action F1 判断模拟器能否用于策略评估：跨 session 中 STA 的 macro-F1/CTR 误差领先，但生产 A/B 对齐上 OPTD 更接近；应同时看轨迹级与结果级校准。
  • OPTD 的配方适合有长轨迹日志的工业用户模拟器：完整轨迹意图只进冻结教师，学生在自生成前缀上接受稠密 token 监督，per-token KL 预算限制教师偏移。
  • Replay 适合低成本回归定位局部动作错误，Rollout 才暴露长程累积偏差；离线策略比较应以 Rollout 结果为主、Replay 为辅。

局限与阅读提醒

  • 即使最佳 OPTD 仍低估生产策略效应 28.7%，所有评测模拟器与线上参考仍有差距。
  • 数据来自单一电商平台，点击中服饰占 54.90%，商品元数据仅标题和英文顶层类目；跨平台/跨品类泛化未验证（分析者判断）。

抖音广告的生成式端到端检索

Generative End-to-end Ad Retrieval at Douyin ↗ 阅读中文全文 →

全文机构行（模型提取） · 论文更新于 2026-09-30（UTC）

有抖音广告大规模线上A/B和部署细节，适合关注生成式推荐落地、语义ID坍缩与碰撞问题的工程师优先阅读。

研究问题

生成式检索把推荐转为离散物品token生成，但在真实大规模场景中，物品tokenizer会因流式分布漂移发生表示坍缩；同时巨大候选池使不同物品共享同一token序列。二者相互耦合：扩大码本缓解碰撞会加剧坍缩。论文要在抖音广告场景中同时解决这两个瓶颈，并实现可端到端训练和实时服务。

核心方法

GEAR联合优化tokenizer、生成器和重排头。Tokenizer采用BasisVQ：把码本重参数化为可学习正交基，用Newton-Schulz迭代保持正交，使梯度作用于整个码本，并通过坐标刚性旋转复用未激活码；再扩展为前缀感知BasisRQ，用前序量化码查表聚合逐元素仿射缩放/偏置，增强码本表达而不提高vanilla VQ的渐近距离计算复杂度。生成器是encoder-decoder；解码后增加一个解码步，复用隐状态与tokenizer物品向量做点积重排，并以LambdaLoss等损失联合训练。

实验结果

  • 抖音广告线上A/B中，GEAR使ADSS提升+0.563%、ADVV提升+0.658%。
  • 子集在线消融中，完整GEAR的ADSS/ADVV相对增益为+0.446%/+0.498%；去掉prefix-aware BasisRQ降至+0.288%/+0.219%，去掉rerank为+0.358%/+0.341%，去掉secpm重加权为+0.395%/+0.354%。
  • tokenizer对比中，BasisRQ较vanilla RQ码本利用率提高3.23个百分点、碰撞率降低20.4个百分点。
  • 冷启动广告激活率取得+1.46%的相对提升。

工程 insight 分析推断

  • 对需要流式更新物品索引的广告/电商推荐，BasisVQ在训练期让梯度覆盖整个码本、推理期码本可离线缓存，意味着可以近线刷新语义ID而不增加线上延迟；前提是物品塔和tokenizer能增量前向。
  • 即使采用prefix-aware BasisRQ，Table 2中碰撞率仍为52.3%，所以重排头不是可有可无的装饰；对同token序列候选密集的场景，应预留item-level消歧和低精度打分链路。
  • 码本容量按残差能量递减分配（如2048,512,128）优于均匀容量，这提示语义ID设计不必每层等大；前层给更大码本、后层更小，可能在同容量下降低碰撞。

局限与阅读提醒

  • 论文明确把更高效解码以降低推理延迟列为未来工作，说明生成式解码仍是线上效率约束。
  • 线上A/B仅覆盖抖音广告7天、以ADSS/ADVV为主，论文未给出置信区间、显著性检验和延迟绝对值，跨平台外推需谨慎（分析者判断）。

以 Semantic ID 作为唯一物品表示的推理式重排

Reasoning Reranking with Semantic IDs as the Sole Item Representation ↗

全文机构行（模型提取） · 论文更新于 2026-10-16（UTC）

对做生成式推荐和 SID 的团队有直接工程价值：给出了 SID 直接用于 listwise 重排的失败模式量化（照抄顺序、推理死循环）、四种后训练方法的配对对照、长历史的 token 成本优势和 rationale 不可信的明确边界；附带可复现测试床与代码数据。

研究问题

推理式重排器（先写 rationale 再排候选）目前都读取物品标题/描述文本，而生成式推荐已把物品表示成紧凑 Semantic ID（SID），其 token 嵌入在行为序列上预训练、可能带有文本没有的偏好信号。但已有 SID 模型只做“从历史生成下一个物品”，没有任何任务要求它对一个外部给定的候选 slate 排序。论文问：只给 SID（不给任何物品文本）时，模型能否对给定候选做推理重排；若不能，哪种后训练能习得该行为。

核心方法

构建 ReRankID 测试床：同一批用户、候选、标签可分别以 SID-only、dense-caption 文本、SID+文本三种对齐渲染呈现，使“是否有元数据”成为受控变量；历史长度 k∈{0..256}、候选数 N∈{10..100} 逐轴变化且嵌套构造，用户与训练集不相交。输出为 rationale 加十个候选索引，主指标 NDCG@5（无效输出记 0），并单独统计 Identity%（原样返回输入顺序）与 Loop%（推理到 token 上限）。以 OpenOneRec-1.7B/8B-pro 为基座，比较 SFT（模仿 Gemini 读 caption 的 hindsight 轨迹）、RFT（拒绝采样自训练）、OPD（在 policy 上蒸馏 SFT 教师）、RLVR（GRPO + 1/log2(1+r) 分级排序奖励），全部用 LoRA 且冻结 SID embedding。

实验结果

  • 未后训练时接口是主要瓶颈：anchor 设置（k=64, N=30）下 8B 模型 SID 输入 NDCG@5 为 .168、Identity% 20.5、Loop% 37.3，1.7B 的 Identity% 达 42.3；换成可读 caption 也不改善排序，1.7B 只是把照抄换成了推理死循环。
  • SFT 在两个规模上都消除了全部 identity 排列与推理死循环，并带来显著排序增益（8B：.237 vs Base .168，配对 95% CI [+.028,+.109]）；RLVR 只在 8B 上显著超过 SFT，达到 .277（+ .040，CI [+.006,+.076]），与读文本的 Gemini 和 GPT-5.6-Terra 参考相当；RFT 在 8B 反而低于 SFT（−.026，CI [−.047,−.005]）。
  • 成本与长历史：anchor 下 SID 提示平均 845 tokens，对齐文本 16,722 tokens；k=256 时文本超过 50k tokens 而 SID 仍低于 2k（约 28 倍差）。8B RLVR 在无历史（k=0）时仍比随机高 +.079（CI [+.039,+.118]），而 Gemini 文本参考在同样 slate 上与随机不可区分；历史变长时 8B RLVR 保持增益，Gemini 反而略降。
  • 成对 rationale 审计（100 用户，双向呈现一致才计入）：8B RLVR 在 trade-off 方面 50:0 胜出、讨论顺序与返回排名的 Kendall τ=1.0，但物品级事实陈述 0:66 落后、用户画像 0:37 落后，只提到约十个候选中的三个（coverage .297 vs Gemini .971）。

工程 insight 分析推断

  • SID 直接做 listwise 重排零样本不可用，瓶颈是训练目标与输出接口而非表示容量：上游模型只被训练成“生成下一个物品”，没有见过候选 slate。工程上要么先做接口级 SFT（可用读文本教师生成 hindsight 轨迹），要么不要上线纯 SID 重排。
  • RLVR 分级排序奖励优于二元 top-1 只在 8B 成立（8B 差 +.045，CI [+.013,+.077]；1.7B 无差异），说明近失样本的稠密信用需要模型容量配合；小模型上把奖励工程当重点可能白费，应优先保证监督信号与接口对齐。
  • 长历史场景可把重排输入压缩成 SID：token 成本低一到两个数量级，且在文本参考因上下文接近上限而停止提升的长度上仍保持增益；但前提是 SID tokenizer 与基座在本平台行为序列上预训练过，跨平台迁移未验证。

局限与阅读提醒

  • 离线评测：单一 Kuaishou 短视频数据与 OpenOneRec SID 词表，每个样本只有一个观测正例、主指标只取决于该正例的返回名次，没有任何线上 A/B 或曝光层面验证。
  • SID-only 模型的 rationale 不可靠：它把有历史支撑的兴趣 attaches 到虚构/错认的物品上（如虚构小说名），因此不能直接作为面向用户的解释；论文建议排序用 SID、解释再用检索到的元数据生成，但该方案未在本文实验验证。
  • 分析者判断：评测用户来自发布 checkpoint 预训练所用的交互数据，存在表示层暴露，论文以 k=0 无历史设置和用户不相交后训练来论证非记忆性，但该论证是间接的，未做去污染重训对照。

当历史误导时：面向指令引导 LLM 生成式推荐的非对称间隔监督

When History Misleads: Asymmetric Margin Supervision for Instruction-Guided LLM Generative Recommendation ↗

全文机构行（模型提取） · 论文更新于 2026-10-01（UTC）

值得读：诊断清楚（影响力不等于支持度、目标分不等于排序），方法只在训练加辅助损失、推理不变，并在工业数据与两个公开基准、六个骨干上离线提升；适合判断是否用于历史冲突场景。但无在线 A/B。

研究问题

指令引导的 LLM 生成式推荐要同时服从当前自然语言请求和用户历史偏好；二者冲突时，历史事件可能压过请求，使推荐偏离显式约束。论文指出把单条历史事件的效应直接变成监督有两个障碍：对预测影响最大的事件未必支持目标；删除某事件虽提升目标分数，也可能更大幅提升边界竞争项，因而未必改善排序。

核心方法

AIMS 用冻结 SFT 模型作参考，对初始 top-10 已命中的训练请求逐条删除单个历史事件，只接受同时提升目标分数与目标-边界竞争项 margin 的删除，缓存最大 margin 作为请求级反事实目标。学生输入完整历史：CE 监督所有请求，辅助 ACS 只在保护集惩罚低于 m_cf−ε 的 margin，目标分数 detach，梯度仅经竞争项。推理沿用原解码器，无删除搜索；默认 K=1、单竞争项。

实验结果

  • 在六个 LLM 骨干和三个数据集上，AIMS 在每一设置都取得最佳 Recall@10 与 NDCG@10。
  • 相对匹配的 Continued CE，AIMS 在每个设置的 Recall@10 都提升，相对幅度 4.0–10.9%。
  • 删除选择消融：改用最大目标提升或最大影响度选择删除后，工业数据上 Llama/Gemma 的 Recall@10 从 7.223/8.609 降至 7.091/8.426 与 7.063/8.312。
  • 在指令-历史冲突请求上，AIMS 相对 Continued CE 的 Recall@10 提升为 +0.558/+0.874 点，高于全测试集的 +0.321/+0.664 点。

工程 insight 分析推断

  • 历史筛选若只看无标签影响度，会选到对预测敏感但不支持目标的条目；只看目标分数 uplift 又可能被边界竞争项更大提升抵消。离线构造监督时应同时验收目标提升和相对固定竞争项的 margin 增益。

多轮搜索智能体强化学习中的证据接地信用分配

Grounded Credit Assignment in Reinforcement Learning for Multi-Turn Search Agents ↗

全文机构行（模型提取） · 论文更新于 2026-10-16（UTC）

如果团队在做 LLM 搜索 agent 的 RL 训练，这篇直接指出 outcome-only reward 会让模型答对但不检索，并给出无需额外模型、rollout 或训练阶段的 token-level 校正方案；有七个 QA 基准、两个 Qwen backbone、消融和 grounding 指标，适合快速判断能否迁移到自己的多轮检索/工具调用管线。

研究问题

GRPO 类 outcome-reward RL 将同一 rollout 的所有 token 赋予相同 advantage，但搜索 agent 的 rollout 同时包含“找到证据”和“使用证据”两种能力。作者发现 Search-R1 在七个 QA 基准上 EM 均升，却在 Bamboogle 上把正确答案中由检索证据支持的比例从 84.0% 降到 42.9%，即准确率提升但 grounding 退化。如何在不增加模型、rollout 或训练阶段的前提下，分别校正搜索与答案的 credit，是本文问题。

核心方法

GCA 先用检索命中 H 与答案正确性 C 诊断 rollout 类型，并把 token 分为 vSearch（首次命中前的有效搜索）、rSearch（命中后搜索/未命中搜索）和 Ans。以 first-hit 为操作代理，按每段控制的子结果设定 residual 符号，再用 λ 控制段间强度；段内用 margin–entropy salience 集中到决策关键 token。残差被门控并限制为不超过原 advantage 的 10%，保持符号不变，只改 token-level advantage，不改 reward、组统计和优化器。

实验结果

  • 在七个 QA 基准、相同训练与检索设置下，GCA 相对 Search-R1 的平均 EM 提升 5.70 分（Qwen2.5-3B, GRPO）和 6.30 分（Qwen3-30B-A3B, GSPO）。
  • Qwen2.5-3B 上，Search-R1→GCA 的 EM 为 37.36→43.06，ToolHit 为 45.79→64.68，SupCor 为 30.21→42.80，答案由证据支持的比例 SupCor/Acc 从 76.9% 升至 93.4%。
  • 预算匹配消融中，把 vSearch 与 rSearch 合并成一个搜索段，平均 EM 损失 2.75 分、ToolHit 损失 10.9 分，并降低全部七个基准；grounded share 从 93.4% 降到 82.0%。

工程 insight 分析推断

  • 工业多轮搜索/推荐 agent 若只用最终 outcome reward，检索命中与答案正确性会共享同一 advantage；GCA 表明把可自动验证的中间子结果作为 token-level residual 的符号来源，可在不增加 rollout 的情况下同时提升准确率和 grounding。适用前提是有可验证的中间信号与 first-hit 这类分段代理。
  • first-hit 分段不是无关紧要的工程细节：合并命中前/命中后搜索会损失 2.75 EM 和 10.9 ToolHit，说明多轮检索 agent 应区分探索性检索与命中后冗余检索，否则命中后搜索会被错误赋予 credit。迁移到推荐场景时需重新定义“命中”信号。
  • 中间信号校正应保持 bounded 和 sign-preserving：论文报告无界变体在 145 步内 actor entropy 从 0.67 升到 6.6 并模式崩溃，而默认 residual 被限制在 outcome advantage 的 10% 以内。工业 RL 管线引入辅助 reward 时，先设小预算和符号保持约束比直接调大辅助信号更稳。

局限与阅读提醒

  • H（检索命中）是用 gold answer alias 的词汇包含匹配，只测答案覆盖而非语义支持，会漏 yes/no 和部分比较类答案，也可能在只是提到答案的段落上误触发；没有 gold answer 时需改用 evidence-entailment judge 或可执行检查，作者未评估。
  • 实验仅两个 Qwen 家族 backbone 和单一检索环境（E5/2018 Wikipedia/top-3/5 turns），其他模型与真实 web 搜索未测；30B 只重训 Search-R1 作为基线，seed 方差仅报告 GCA；salience 权重固定且未测其开销。

当智能体检索静默失败：框架与创意 AI 助手的生产证据

When Agentic Retrieval Fails Silently: Framework and Production Evidence from a Creative AI Assistant ↗

全文机构行（模型提取） · 论文更新于 2026-10-21（UTC）

适合正在做 LLM/RAG/agentic 搜索、会话式推荐或检索归因的工程师：失败模式、日志字段和指标计算讲得具体，可直接指导埋点；但只有单产品生产分析，无模型对比或线上 A/B。

研究问题

传统 CTR、MRR、NDCG 假设用户直接看到排序结果、在查询后很快行动，且行为能反映检索质量。Agentic 助手中生成层先消费检索结果，导致“谁先看、何时行动、结果由检索还是生成导致”的归因缺口。论文要解决生产环境中的检索质量度量与归因问题。

核心方法

LARA 将评估拆为三层：Layer 1 在检索触发时用完整排序列表和离线相关性标签计算 null rate、precision@K、NDCG@K；Layer 2 用 GPR、ACR、ORF/UOR 分别记录用户/智能体使用与检索失败信号，并按检索角色标签报告；Layer 3 用导出/分享/下载和按角色的任务完成衡量产品成功。三层通过 retrieval_id、returned_asset_ids、consumed_asset_id、source_retrieval_id 四字段血缘连接，均为日志改动，无需新模型；planner 路由留作 Layer 0。

实验结果

  • Adobe Express 2026 年 8 月生产对比中，chat 用户改写率 44.4%，图库搜索 33.1%（高 11 个百分点）；作者指出 chat 改写主要是在生成输出上继续调整，不能把这一聚合指标直接读作检索失败。
  • 同一检索基础设施上，助手仅 0.31% 的 in-scope prompts 触发检索；检索触发时 null rate 1.51%，用户每个返回网格约点击 1.05 次。
  • LARA 的 GPR、ACR、ORF、UOR 需要 consumed_asset_id、source_retrieval_id 和 retrieval role tag；当前 Express 还需人工 trace annotation，说明多数 Layer 2 指标尚不能自动计算。
  • 用户主动使用/有意义动作的定义会显著改变指标：Express chat 的 meaningful-action rate 随合格动作集合从 7.6% 变到 40.5%。

工程 insight 分析推断

  • 对 agentic 搜索/推荐，检索离线指标应在检索触发时对生成前完整排序列表计算，而不是用点击或会话重试；否则智能体先筛选会让未展示结果无法评估，模型补偿还会掩盖坏检索。适用条件：能记录 returned_asset_ids 和离线相关性标签。
  • 把 retrieval_id、consumed_asset_id、source_retrieval_id 作为跨轮次/跨会话血缘，可把延迟导出归因到具体检索事件；这对多轮对话式推荐尤其关键，因为会话边界会把成功误判为放弃。前提是动作事件统一埋点。
  • 上线时不应把总体 reformulation 当检索质量：需按检索角色拆分 Search Reformulation 与 Downstream Correction，并监控 planner 是否该触发检索；在检索触发率极低的产品里，漏检索可能比排序误差更影响体验。

  • 作者明确：所有证据来自单一 Adobe Express 部署，0.31% 检索率和改写反转可能只适用于生成式编辑主导的创意助手；且血缘字段均未实现，Layer 2 数字仍是基于时序的推断，检索角色为事后推断，跨会话导出会高估聊天放弃率。

从延迟单侧反馈学习个性化记忆门控

Learning Personalized Memory Gating from Delayed One-Sided Feedback ↗

全文机构行（模型提取） · 论文更新于 2026-10-16（UTC）

如果读者在做 LLM 代理长期记忆、个性化召回或资源受限的检索门控，这篇把“事实是否值得存”转成可在线学习的延迟反馈问题，并给出离线基准与 UCB 方案；但收益仅在构造基准上验证，不是通用推荐排序论文。

研究问题

LLM 代理的长期记忆库容量有限，必须在抽取事实时决定存或弃。现有门控策略多在用户间共享，忽略个体复用模式差异；而真实效用信号只有在该事实被存入、且未来被检索并用于回答时才出现，具有单侧、延迟和截断特征。论文要解决事实级个性化记忆门控的学习问题。

核心方法

论文先用“后续是否被检索并进入回答”构造事实效用标签，并用 LLM judge 过滤仅主题相关的命中；再把事实级存/弃决策建模为带单侧延迟反馈的上下文苹果品尝问题。Warm-Start UCB 分两段：用其他用户数据离线拟合线性先验，在线用 ridge UCB 从该先验出发适配当前用户；对延迟采用长度 m 的截断观测，并按延迟分布质量 κ_m 校正阈值。理论上给出 O~(min{Tε,(d√T+md)/κ_m}) 的高概率 regret 上界。

实验结果

  • 在 PerMemBench-S（20 用户构造基准）上，Warm-Start UCB 在预算 60/120/250/500 的 micro RHR 为 24.10/38.64/58.73/84.48，macro 为 26.40/41.98/61.84/86.94；指标为检索命中保留率。
  • 同一基准上，作者报告 Warm-Start UCB 在每个记忆预算、micro 与 macro 两种平均下均优于 Universal 与所有 LLM 门控基线；这是离线基准比较，不是线上 A/B。
  • 在更长的 PerMemBench-L 上，Warm-Start UCB 在十个评估列中有八列是非 Oracle 最佳，另两列第二，说明长交互下仍具竞争力。
  • 消融显示，预训练用户池从 1 增加到 15 时，micro/macro RHR 在每个预算下单调提升，且到 15 个用户仍未饱和。

工程 insight 分析推断

  • 对工业记忆/召回系统，可把“事实之后被检索并进入回答”作为写入策略的弱监督信号；先离线回放日志构造标签，再用 LLM judge 过滤主题相关但非必要的命中。适用前提是系统能保留事实级检索与引用链路，且能承受 judge 成本。
  • 跨用户先验与在线适配合用比单用任一侧更稳：冷启动/反馈稀疏时先验贡献大，交互变长后在线 UCB 才逐步体现用户差异。工程上可按用户交互量设置先验权重或切换点，但需防止早期探索把有限记忆槽位浪费在低效用事实上。
  • 延迟窗口 m 和延迟分布质量 κ_m 不是实现细节，而是决定截断标签偏差与阈值校准的关键；线上若延迟远大于假设，应扩大窗口或改用生存/删失建模，而不是直接套用固定 m。

局限与阅读提醒

  • 论文明确假设每个用户的门控参数稳定，未建模用户效用模式随时间的演化。
  • 在线模型简化了已检索事实的效用强弱差异，也未建模记忆库接近满时存储成本随时间变化。
  • 分析者判断：所有实验均在构造的 PerMemBench-S/L 离线基准上，未提供线上 A/B 或真实产品部署证据；真实延迟分布和检索噪声下的外推需谨慎。

语义ID生成式推荐的三种落地路线：表示容量、排序接口与多域后训练

当前样本围绕语义ID形成三类互补取舍。GEAR优先解决表示层：用BasisVQ让梯度覆盖整个码本、以前缀感知BasisRQ增强表达，再用轻量重排头处理同序列碰撞，目标是训练-服务一体和低延迟，但代价是tokenizer与索引需支持近线刷新，且碰撞率仍不低。SID重排把问题移到任务接口：纯SID输入下现成模型会照抄候选顺序或陷入推理循环，SFT先教会listwise输出，RLVR的分级排序奖励只在8B上显著超过SFT，说明奖励工程受模型容量约束。OneReason挑战赛则展示多域后训练取舍：CoT不必然提升推荐，自采样轨迹需掩码目标SID以保持候选多样性，think/nothink可按域选择，分层奖励要防止只提升浅层码准确率。工程建议（推断）：先量化SID碰撞率与模型照抄/循环率；有稳定日志时先用SFT对齐候选slate接口，再评估RL；低延迟广告召回可优先GEAR式码本与轻量重排；多域系统先做分域监督和分层信用分配，不要默认CoT或统一奖励可迁移。
