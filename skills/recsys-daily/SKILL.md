# 推荐研究日报

由当前 harness 的模型和工具完成检索、阅读与写作，直接操作静态页面，不运行 `pipeline.py`、`collect_daily.sh`，也不要求配置独立模型 API。Python 渲染函数只用于离线排版，不启动采集或数据库任务。

## 开始工作

定位包含 `paper_catalog.json`、`pipeline_config.json` 和 `docs/` 的仓库根目录，读取 `AGENTS.md` 与本地 Git 状态。技能安装目录不一定是仓库目录；不要写死绝对路径或原作者仓库地址。

确认归档日期（默认北京时间当天）、篇数和是否发布。沿用当前 `digest.min_papers` / `max_papers`，目前默认 5 / 10；用户参数优先。用户只要求生成时，完成本地页面；用户要求发布时继续到线上验证，无需重复询问。

## 仅发布已有日报

用户只要求发布时，先查 `reports/daily/<日期>.json`、`reports/site/<日期>.html` 和 `docs/<日期>.html`。复用已经完成的解读；已有完整 HTML 则直接检查并同步，缺页面但有 JSON 时按构建文档离线渲染。更新首页与归档后进入发布流程，不重新检索。不具备完整产物时说明缺什么，不把空页面当成成功日报。

## 发现与筛选

- 用 harness 可用的 web search / fetch、浏览器或连接器检索。组合主题、公司及时间窗口，不能只复制聚合站日报。
- 推荐系统优先，兼顾相关检索、生成式检索和 LLM。读取配置的公司名单、优先公司和 `company_aliases.json`；至少一位作者有可核实的大公司署名，不能将学校、数据集名称或被引用公司当作作者机构。
- 以归档日为窗口结束日期，按配置的 7 → 14 → 30 天回溯补齐。记录官方首次提交与修订日期、固定版本；不要收录归档日之后才出现的版本来冒充当时成果。日期模糊时查原始记录。
- 通过 arXiv 官方摘要页、HTML、源码或作者页面核实标题、作者、版本和机构。官方 API 是可选核实工具，不是规则采集入口。按无版本 arXiv ID 去重，并检查 `docs/` 已有日报，默认避免近期重复；明确标注必要的修订重访。
- 搜索命中只是候选。把来源 URL、选择理由、机构证据与失败原因持久化，失败后换源；限制重试与总预算，不能无限搜索或编造论文凑数。

## 全文解读与综合

生成或重写解读前，阅读 [可读性写作与验收](references/readability.md) 和 [日报数据与构建](references/digest.md)。默认读者了解推荐/机器学习基本概念，但没有读过这些论文、不熟悉各论文自造的模块名。目标是让读者理解问题、方法机制、实验证据和适用条件，再决定是否读原文。用户指定读者或深度时，以用户要求为准。

逐篇读取正文、实验和局限，HTML 不可用时尝试源码或 PDF；需要 PDF 工具时使用当前环境可用能力。仅拿到摘要的条目留在待重试列表，不计入已完成全文解读。用户要求重读、完全重写时，保留指定选文和版本，返回全文或核验过的固定版本快照重新阅读，从原文重建解读，不能只替换旧摘要的措辞。

先形成可回查的阅读笔记，再写读者正文。笔记记录章节、表格、公式或稳定文本块定位，以及关键设置与证据；正文按“场景与障碍 → 方法怎样解决 → 结果与条件 → 工程取舍”组织，不沿论文顺序压缩所有细节。涉及多阶段训练或多模块系统时，说明谁被训练、谁被冻结、哪些组件只在训练中使用、哪些进入在线服务。

分别写研究问题、核心方法、实验结果、工程推断和局限，再综合跨论文趋势和专题。可参考 `prompts/paper_insight.txt`、`prompts/daily_synthesis.txt` 的事实与字段要求，实际文件名先检查，不调用 provider；正文解释顺序、详略及可读性以本 skill 的写作指南为准，不为迁就提示词中的短字数建议而把方法压成术语串。

JSON 结构必须有效。数字与引用自动检查只作为提示，不因机械匹配失败阻止日报；证据缺失时修正或移除具体断言，不制造引用。记录全文实际读取范围，不在页面追加通用 AI 免责声明或篇数不足横幅。

交付前逐篇执行写作指南中的复述检查，再检查跨论文综合。发现无法从正文解释的关键术语、因果跳步或指标误读时，回到相应段落补写或重写；JSON 有效、数字可匹配、页面排版正常都不能替代内容可读性验收。记录实际发现及修订，不只填写“通过”。仅发布已有成稿时不自动启动全文重写。

## 构建与交付

按引用文档生成 Markdown / JSON 与 HTML，维护首页和日报归档；从当前 `docs/` 开始保留全部已有日报、论文和资源。克隆仓库通常没有 `reports/daily/`，不要用空本地历史覆盖线上归档。

读取 [静态站点发布](../references/publishing.md)，完成本地链接、手机/桌面页面检查；有发布授权时提交、推送并验证。输出日期、实际篇数、本地文件与线上链接；不足时如实说明，保留可恢复结果，不假报完成。日志保存到实际运行日期的 `logs/YYYY-MM-DD/HH-MM-SS.log`，包含 INFO / WARNING / ERROR、失败 URL 和异常堆栈，不能记录密钥。
